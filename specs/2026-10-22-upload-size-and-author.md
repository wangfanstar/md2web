# 上传大小配置与文档作者显示

## 上传大小

- 默认单文件上限 500 MB，1 MB 按 1024 × 1024 字节计算；允许恰好达到上限。
- 管理员在 `md2web_config.html` 的「缓存与性能 → 上传大小」设置 1–500 的整数，点击「保存全部修改」。配置键为 `uploads.maxFileMB`，保存到运行配置、当前 JSON 方案和私有备份；旧方案缺少此键时使用 500 MB。切换方案也会切换上传限制。
- 参考文献 PDF/Word/Excel/PPT、编辑器图片/附件及反馈图片/附件共用限制。限制不影响只在浏览器保存的 AI 检索文档容量。
- 服务端每次请求读取当前限制，保存配置后立即生效；前端通过登录状态接口读取当前值，已打开页面在会话刷新或重新打开后使用新值。服务端始终执行最终校验。
- 请求体上限为单文件上限的 base64 编码长度加 1 MB 包装空间，避免原始文件未超限却被 JSON/base64 传输体积拒绝。
- 参考文献多选文件按总原始大小自动分批、依次上传，保留同名 `file` 多值字段及逐文件结果。单文件超限不会写入目标文件；超大请求返回 413 和分批提示。上传失败原因保留在界面上，不被刷新列表清空。

## 文档作者

- 正文顶部显示「最后更新：日期 · 作者：账号」。
- SVN 文档使用已发布提交记录中的账号，缺少记录时读取 SVN 日志作者；本地文档使用内容匹配的最近在线保存账号。
- 无可靠作者记录时显示「未知」；本地文件在站外被修改后不再归给旧保存者。作者以纯文本显示。

## 验证与部署

- Python 3.6.8 回归覆盖默认值、配置校验/JSON 往返与方案快照、每文件边界、base64 传输空间及请求体限制、作者来源和本地内容核对。
- 浏览器回归覆盖配置保存、范围校验、会话下发限制、多文件分批、超限文件、具体服务端错误保留，以及匿名阅读时显示作者与作者文本安全。
- 修改源码后已通过离线构建同步生成资源；部署更新后重启认证服务并重新打开页面。此后仅修改上传大小无需重启。
- 验收结果：Python 3.6.8 全量 589 项通过（跳过 1 项），Node 全量 140 项通过，全部前端 JavaScript 语法检查通过，三组浏览器回归（配置页、上传大小与分批、作者显示）通过。Windows 上全量验证将 Git for Windows 的 `usr/bin` 放在 PATH 前端，避免误选 WSL shell。
