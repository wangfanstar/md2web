# 其他 IP 访问记录缺失修复

## 原因

此前前端在未登录时不发送阅读事件，后端也拒绝匿名访问记录；仅查看首页的访问没有采集。因此其他设备未登录或没有打开文章时，不会出现在用户记录中。统计 Tab 再次打开还会继续使用内存缓存，导致已采集的新记录不能立即显示。

## 调整

- 认证服务对成功的 HTML 页面 GET（包括首页、仓库、配置和参考资料页面）采集 `site_visit`；排除脚本、样式、API、lib 资源和失败响应。
- 文章访问接口允许未登录访客，要求 JSON 并校验同源；登录用户仍要求 CSRF，且仅记录存在的 Markdown 文件。登录失败、成功登录、页面访问与文章阅读分别聚合。
- 匿名访问在 IP 列表明确标为“未登录访客”，不再错误地将文章路径当用户名。管理员才能查看统计；不将 IP 作为登录身份或赋予权限。
- IP 明细增加访问页面/文章路径；同一 IP 不同页面分别聚合，输入 IP 可查看其访问的具体路径及次数。
- 文章访问次数包含匿名阅读；阅读人数按登录账号或匿名 IP 去重（同 IP 多人可能合并）。账号排行榜仍只统计已识别账号。
- 每次打开用户记录 Tab 都重新请求，避免无限复用旧数据。访问采集不会清空文档和文件夹元数据缓存。

统计从此次修复后开始补齐；过去未采集的访问无法还原。本实现使用连接来源 `remote_addr`，不盲目信任客户端提交的 X-Forwarded-For。如果部署在反向代理之后，需配置可信代理传递真实地址；代理直接分发的 HTML 请求不会进入 Python 页面记录，文章前端事件仍通过认证 API 采集。

## 验证

HTTP 回归模拟 10.2.3.4 首页访客与 10.2.3.5 匿名文章访客，验证管理员可查询两者；跨站采集拒绝，匿名查询统计拒绝。真实浏览器验证已登录及独立匿名会话均被采集，打开/刷新文章去重逻辑不变。配置页浏览器回归验证刷新与筛选。
