# Visual PCS · 800GBASE-R 三维通道逐项核对

核对基线为页面版本 `35bb1cd`。按 [IEEE Std 802.3df-2024 本地 PDF](../docs/pdf/8023df-2024.pdf) 的 Figure 172–2 和 Clause 173，沿 [800GBASE-R 标签页](../docs/html/ref/visual-pcs.html) 当前选择的 32 条 PCS lane → 8 条物理 lane 路径核对。下表的“已绘”表示存在可辨认的场景节点，“合并”表示多个动作共享一个节点，“缺”表示在当前场景中找不到对应处理。判断依据为[场景定义和点击详情](../docs/html/ref/visual-pcs-assets/pcs-800g-view.js)及[示例数据模型](../docs/html/ref/visual-pcs-assets/pcs-800g-model.js)，采用静态源码核对，未做浏览器逐帧验收或协议一致性测试。

## 首要发现：两个 Flow 的立体方块没有画全

场景的 `modules` 数组只在 TX 上排声明 Flow 0 的转码、加扰、AM/FEC、16 lane 四个方块，只在 RX 下排声明 Flow 1 的 FEC、解扰、逆转码三个方块。`addModules()` 按条目的 flow 值筛选后创建网格，不会为另一排自动复制。因此 **TX Flow 1 缺四块，RX Flow 0 缺三块**。数据模型里存在两条流，连线或弹窗能描述两条流，但读者沿另一排无法逐块点击对应实体。共享的分流、合流、PMA 和全局对齐节点只需画一次。

## PCS 发送：从 800GMII 到 32 条 PCS lane

| 标准条款 | 处理项 | 当前场景与核对结果 |
|---|---|---|
| 172.2.4.1 | 64B/66B 编码 | 已绘。TX MAC 后有公共编码块，示例展示纯数据块，未演示控制块。 |
| 172.2.4.2 | TX rate matching | 缺。编码到分流之间没有 Idle 调整节点或前后块序列可查。 |
| 172.2.4.3 | 66b block distribution | 已绘。公共分流节点将连续块交替送往 Flow 0、1。 |
| 172.2.4.4 | 256B/257B 转码 | 部分已绘。模型按每流四块转码，TX 仅 Flow 0 有实体；示例限于纯数据。 |
| 172.2.4.5 | 加扰 | 部分已绘。每流独立加扰，TX Flow 1 缺实体。 |
| 172.2.4.6 | AM 映射及插入 | 合并在 AM/FEC。详情给出 AM 组和周期；示例码字由重复数据块构造，无法追踪含 AM 的实际码字。 |
| 172.2.4.7 | FEC 前分配 | 合并在 AM/FEC。模型按 10 bit 符号向 A/B 分配，场景没有单独分配节点。 |
| 172.2.4.8 | RS 编码 | 合并在 AM/FEC。模型生成每流 A/B 两个 RS(544,514) 码字，TX Flow 1 缺对应方块。 |
| 172.2.4.9 | FEC 符号分发 | 合并在 AM/FEC 到 16 lane 的路径；可按 lane 查看符号，TX Flow 1 缺 16 lane 实体。 |
| 172.2.4.10 | 符号次序 | lane 数据详情承载次序信息。这是分发时须满足的顺序约束，可用码字号、符号号和 lane ID 验收，无须另画硬件。 |
| 172.2.4.11 | Scrambled Idle 测试模式 | 缺测试入口。属于测试路径，应与日常业务流分开展示。 |

## PCS 接收：从 32 条 PCS lane 到 800GMII

| 标准条款 | 处理项 | 当前场景与核对结果 |
|---|---|---|
| 172.2.5.1 | AM 锁定、lane 对齐和 deskew | 已绘共享 AM/Deskew。模型模拟失锁、偏斜和恢复，未逐位执行完整的锁定状态机。 |
| 172.2.5.2 | lane 重排及去交织 | 合并在 AM/Deskew 和 RX FEC 的交界。模型利用已知 lane 标识重组 A/B 码字，缺少可单独观察的重排前后序列。 |
| 172.2.5.3 | RS 解码 | 部分已绘。模型可注入符号错、解码并报告结果；RX Flow 0 缺 FEC 实体。 |
| 172.2.5.4 | FEC 后交织 | 缺。解码所得 A/B 消息符号交替恢复为单条流的动作没有独立呈现，也没有可追踪的输出交给后级。 |
| 172.2.5.5 | AM 移除 | 阶段文字并入 RX FEC；无法看到接收序列中 AM 被识别、删除以及相邻数据接续。 |
| 172.2.5.6 | 解扰 | 部分已绘。RX Flow 0 缺实体；详情的解扰输入来自同一示例的加扰结果，未贯通前级 RS 解码输出。 |
| 172.2.5.7 | 257b 逆转码 | 部分已绘。RX Flow 0 缺实体，示例恢复四个纯数据 66b 块。 |
| 172.2.5.8 | 66b block collection | 已绘。公共合流节点按两流交替恢复块序。 |
| 172.2.5.9 | 64B/66B 解码 | 已绘。可以查看数据块还原为字节，控制块及错误传播未在示例中展开。 |
| 172.2.5.10 | RX rate matching | 缺。解码至 RX MAC 之间未表现接收端允许的 Idle 补偿；演示应标注其适用条件。 |

## 补图验收顺序

1. **先补七个对称方块。** 暂停动画，沿 TX 和 RX 的上下两排分别点击，检查详情中的方向、Flow ID 和数据与所点实体一致。
2. **再补 PCS 断点。** TX 演示速率匹配和 AM 插入；RX 将同一码字对的纠错输出送入 FEC 后交织、AM 移除和解扰。在 AM 边界两侧标出数据块号，并展示 RX Idle 补偿条件。
3. **最后展开 PMA 接收及条件功能。** 用一个可辨认的电平序列连接 TX 映射、物理 lane、RX 判决和解复用；按所选接口展示预编码能力及启用状态。测试模式、环回与时延约束可留在详情或独立入口。
