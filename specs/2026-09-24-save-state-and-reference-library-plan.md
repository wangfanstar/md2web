# Markdown 保存状态修复与参考文献库实现方案

日期：2026-09-24  
状态：方案稿；本轮只分析和编写方案，不修改业务代码、不安装转换器、不创建源资料。

## 1. 目标与推荐方案

1. 修复 Markdown 文件已经保存、界面长时间等待且关闭仍提示未保存的问题。
2. 在 `docs/` 下增加 `pdf/`、`word/`、`excel/` 三个源资料目录，支持任意层级子文件夹。
3. `docs/index.html` 增加“参考文献”组，列出三个目录的一级子文件夹；进入对应独立 HTML 页面后可以浏览、预览、上传、删除、恢复、移动、重命名和按文件夹分组。
4. 保持离线使用、Python 3.6.8、现有认证与只读预览约定。原始文件保存在磁盘，索引和预览都是可重建的派生数据。

方案比较：

| 方案 | 优点 | 局限 | 结论 |
|---|---|---|---|
| 为三种格式各做一套文件管理 | 可单独定制 | 权限、回收站和移动逻辑重复，容易出现行为差异 | 不选 |
| 共用文献管理器，按格式提供预览适配 | 操作统一，兼容现有架构，便于离线部署 | Office 高保真预览需要本地转换能力 | 推荐 |
| 接入在线 Office/云盘服务 | 可提供在线协作编辑 | 依赖网络、账号与外部服务，不符合完全离线约定 | 不选 |

本期 Word、Excel 的“相同处理”定义为文件管理与只读预览，不包含网页内编辑 Office 内容。分组直接对应真实文件夹，避免标签组与目录两套规则。

## 2. 保存问题：代码证据与修复路径

### 2.1 已确认的调用关系

- `web/md-editor.js::publishToServer()` 发起 `POST /__md/publish`；只有收到响应后，才更新 `state.original`、`state.baseHash`、`publishedOnServer`。
- `server/app.py::pending_publish()` 先调用 `local_publish_content()` 或 `publish_file()` 写入，再同步调用 `on_config_changed()`，最后返回成功 JSON。
- `serve.py::rebuild_sites()` 使用重建锁并执行整站构建。因此文件已落盘后，HTTP 请求仍可能等待前一次构建和本次构建。
- `close()` 使用 `isModified()` 判断关闭提示；`beforeunload` 还会检查全站 `pendingDrafts`。当前文档保存成功与其他文档存在未提交 SVN 草稿，是两种不同状态。

这解释了“文件已保存但前端迟迟未确认”的主要机制。是否另有响应异常、返回 hash 字段差异或换行规范化问题，实施时通过接口回归与浏览器复现验证，不预先断言。

### 2.2 服务端改造

- 文件及必要数据库状态成功落地后立即返回保存结果；响应含 `saved=true`、规范化路径、内容 hash、保存请求 ID、站点更新任务 ID。
- 增加单一后台重建调度器，统一接收编辑保存、目录操作和监视器事件。合并短时间重复请求，串行执行；构建期间的新变更必须触发下一轮，不能丢失。
- 状态区分 `queued/running/succeeded/failed`，提供任务状态查询。进程重启后根据源文件变化补建，不能依赖内存队列实现数据持久性。
- 重建失败只表示索引/页面未更新，不能把已经持久保存的文件报告为“保存失败”；界面提供“重试更新站点”。
- 数据库访问使用现有共享锁，锁内不执行构建或转换。核查本地 SQLite 文本库和文件物化的失败恢复，不扩大本次存储架构改造范围。

### 2.3 编辑器改造

- 状态明确为“有修改 → 保存中 → 已保存；站点更新中 → 已保存；站点已更新”。
- 保存时捕获 `resource/content/baseHash/editorSessionId`；响应只更新发起请求的编辑会话，防止切换文档后旧响应污染新文档。
- 同一文档保存串行化，重复点击复用进行中的请求。用户可继续编辑，但成功响应只确认已发送的那一份内容；之后的修改继续显示未保存。
- 以服务器确认的内容与 hash 更新基线，统一换行比较；修复各保存路径返回字段不一致的问题。
- 关闭期间若保存仍在进行，提示“正在确认保存结果”；网络断开时核对服务器内容 hash，无法确认则保留本地修改，不能直接标记已保存。
- 当前文档未保存提示与未提交 SVN 草稿提示分开。完成本地发布后仅清理与该次发布一致的旧草稿，不能清掉并发产生的新草稿或其他文档草稿。
- 保存成功关闭编辑器不依赖整页刷新；刷新当前正文，站点索引按后台任务完成状态更新。其他草稿保留明显提示，不伪装为当前文档未保存。

验收重点：构建回调被阻塞时，保存接口仍能完成；保存中继续输入的文本仍受保护；连续保存、冲突、断网和切换文档时不误报成功、不覆盖内容。

```text

    index_word.html
    index_excel.html
  lib/reference-library.js
  lib/reference-library.css

  reference-previews/          # Office 转换缓存；不直接静态暴露
  reference-trash/             # 本地参考文献回收站及原路径记录
```

- 首页“参考文献”组中以 PDF / Word / Excel 类型小标题区分，卡片展示一级文件夹名、文件总数、最近修改时间；同名目录用类型徽标区分。
- 每类保留“全部 PDF / Word / Excel”入口，确保根目录文件和空库都可访问；空库显示“上传文件 / 新建文件夹”，不能因没有 Markdown 文档而无法构建文献首页。
- 每个一级子文件夹生成 `html/index_<类型>_<文件夹名>.html`；中文保留，URL 编码，非法字符替换后冲突使用稳定短摘要后缀。页面名称生成规则只维护一处。
- 子文件夹使用同一入口页的查询参数导航，不为每层生成一套页面；服务器根据类型、库根和相对路径校验，前端参数不能突破类型根目录。
- 所有入口保持 `<base href="../">`；页面间链接为站点根相对路径，避开 Docsify 的 hash 路由拦截。
- 构建不创建、移动或改写用户资料；目录初始化由专门初始化步骤或管理接口执行。仅清理确认为生成物的过期入口页。

## 4. 用户操作方案

页面采用“左侧文件夹树 + 顶部面包屑/工具栏 + 中间文件列表 + 预览面板”。文件列为名称、格式、大小、修改时间、预览状态，默认文件夹优先、名称排序，支持搜索当前库的文件名和路径。

- 点击文件打开预览；工具栏提供上传、创建文件夹、刷新、回收站。支持多文件上传及拖入上传，显示逐文件进度和失败原因。
- 文件/目录右键菜单和行尾菜单提供相同操作，触屏用户不依赖右键。
- 重命名保留扩展名并显示完整目标名；同名冲突默认拒绝并提供另存名称，绝不默默覆盖。
- 移动弹出目标文件夹树，支持同类型跨一级目录移动；禁止把目录移入自身或其子目录。第一期不跨 PDF/Word/Excel 类型移动，避免扩展名规则和首页分类混乱。
- “新建分组”即新建文件夹；“归入分组”即移动到文件夹。支持多选移动、删除，各项结果单独反馈。
- 删除先进入参考文献回收站，记录原类型、完整路径、删除人、时间和版本；支持原位置恢复、选择其他恢复位置、单项永久删除和清空。
- 恢复目标存在时必须选择新位置或新名称，不覆盖原文件。彻底删除只移除该条目的文件和预览缓存。
- 本次新建三个资料目录默认是本地库，不自动绑定或提交至任意现有 SVN 库；现有 Markdown 的 SVN 回收站规则不变。若后续需要文献 SVN 管理，单独增加类型化仓库映射。

## 5. 预览策略与离线边界

| 格式 | 首期处理 | 失败或未安装转换器时 |
|---|---|---|
| PDF | 使用浏览器内置 PDF 查看能力，支持新窗口打开和下载原件 | 明确提示下载后用本机阅读器打开 |
| DOC/DOCX | 认证服务调用管理员配置的本地 Office 转换器生成 PDF，统一只读预览 | 显示“尚未配置预览转换器”，允许正常管理、下载原件 |
| XLS/XLSX | 本地转换为 PDF，按工作簿打印设置预览；提供原件下载 | 同上；提示 PDF 预览可能受工作表打印区域影响 |

- 不承诺浏览器直接高保真渲染原生 Word/Excel；本地转换属于额外可选部署组件，不增加 Python 3.6 核心依赖。实施前用目标 Windows/Linux 环境验证转换器版本和样本效果。
- 转换在后台任务运行，独立临时目录、低权限进程、禁用宏执行与外链更新，限制时间、并发、源文件大小和输出大小。输出转换失败、受密码保护等明确原因。
- 缓存键由源文件内容 hash、转换器版本、预览选项组成。移动/重命名可复用内容缓存，源文件变化自动失效。
- 转换任务不占用数据库锁，不修改原件；超时结束该转换子进程，不影响站点服务。没有转换器时不反复提交无效转换任务。
- HTTP 服务允许内嵌 PDF，确认 MIME、Content-Disposition 和 Range 请求支持；Office 原件以下载方式提供。预览失败仍保留下载入口。
- `file://` 使用构建产生的文献清单，可浏览目录并打开 PDF/下载原件；写操作显示只读说明。Office 转换需要服务端，不把运行时缓存或私有临时文件偷偷复制进公开站点。
- 首期仅搜索文件名/目录名，不把 PDF、Office 正文伪装成已加入 Markdown 全文索引；OCR、Office 在线编辑、公式重算不纳入本期。

## 6. 服务端接口与安全约定

新增独立 `/__references` API，复用认证、CSRF、审计和错误格式；不放宽 `server/documents.py` 对 Markdown 的约束。

| 接口 | 用途 |
|---|---|
| `GET /__references/tree?kind=pdf` | 文件夹树与库列表 |
| `GET /__references/list?kind=pdf&path=通信标准` | 分页文件列表、排序、文件名过滤 |
| `POST /__references/upload` | multipart 上传到指定类型和目录 |
| `POST /__references/mkdir` | 新建目录/分组 |
| `POST /__references/rename`、`move`、`delete` | 单条或批量文件操作 |
| `GET /__references/trash` | 回收站列表 |
| `POST /__references/restore`、`purge` | 恢复与永久删除/清空 |
| `POST /__references/preview` | 按文件版本请求预览任务 |
| `GET /__references/preview/<jobId>` | 转换状态 |
| `GET /__references/preview/<jobId>/file` | 校验后的 PDF 预览输出 |

- 与现有文档相同：资料阅读公开、写操作需要登录和 CSRF；只读预览服务拒绝写入。参考文献创建后默认采用站点登录用户可管理的模式，并在配置中提供禁写开关。
- `kind` 只允许 `pdf/word/excel`，用户不能指定任意系统根目录；拒绝路径穿越、符号链接/junction 越界、保留名、隐藏系统文件及不支持的扩展名。
- 校验扩展名和实际文件签名；DOCX/XLSX 对容器大小、条目数量和解压大小限额，拒绝宏格式及可执行伪装，不解压到用户指定位置。
- 上传默认每文件 100 MiB、可由管理员调整；分块落盘并计算 hash，不将整个文件读入内存。第一期不做断点续传。
- 操作携带请求 ID 和文件版本（hash 或可靠版本标识）；并发变更返回 409。批量返回逐项结果，禁止失败后将整个批次显示为成功。
- 回收站不能通过静态白名单直接下载；元数据存储和操作日志不得放进公开页面。目录操作与构建扫描共享一致性约定，避免半写入文件进入索引。

## 7. 代码划分与实施顺序

### 阶段 A：修复保存状态（独立交付）

- 修改 `server/app.py`、`serve.py`；新增 `server/site_jobs.py` 管理重建调度和状态。
- 修改 `web/md-editor.js`：保存快照、请求串行、状态拆分、关闭与草稿提示。
- 先写回归用例：阻塞构建不阻塞保存响应；保存期间二次编辑；旧请求晚到；草稿提示；冲突和请求结果不确定。
- 新增 `tests/test_editor_save.js`，扩展 `tests/test_server.py`，验证成功后再构建并实测。

### 阶段 B：文献目录与只读浏览

- 新增 `server/references.py`：类型根目录、扫描、路径验证；新增 `web/reference-library.html`、`.js`、`.css`。
- 修改 `setup_docsify.py`：文献清单、根入口、一级文件夹入口、“参考文献”首页组；支持仅有文献没有 Markdown 的站点，保持真正空站点明确错误。
- 修改监视逻辑监听三类资料目录，包含空文件夹变化、删除和重命名；初次初始化三类目录，在空目录中保留非内容占位文件并由扫描器忽略。
- 测试中文/空格/同名文件夹、命名碰撞、空库、目录递归、离线清单、过期生成物清理，以及构建前后原件 hash 不变。

### 阶段 C：文件操作与回收站

- 新增 `server/reference_operations.py`，路由放入独立模块后注册到 `server/app.py`；元数据沿用 SQLite 3.7.17 可用语法。
- 实现上传、文件夹、重命名、移动、删除、恢复和清空；复用锁/认证/审计基础设施，但不直接套用仅适用于 `md/` 与 SVN 的路径规则。
- 将文献回收站入口接入现有回收站页面，按“Markdown / PDF / Word / Excel”展示，防止不同回收站 API 混用。
- 先测试越界、重复请求、同名冲突、移动失败恢复、批量部分失败、权限和逐项永久删除，再接入前端操作。

### 阶段 D：预览与交互完善

- 新增 `server/reference_preview.py` 及转换任务状态；实现 PDF 预览与可选 Office 转换适配。
- 完成面包屑、文件夹树、多选、右键/行尾菜单、进度、错误重试、键盘焦点及小屏布局；使用 `--docs-*` UI 变量。
- 测试转换器缺失、失败、超时、损坏文件、加密文件、缓存命中和源文件变更失效；人工验证多页 PDF、含表格 Word 和多工作表 Excel。

### 阶段 E：文档、验收与存档

- 更新 README.md、AGENTS.md：目录职责、接口、原件保护、转换部署、只读限制和测试命令。
- 仅用 Python 3.6.8 跑 Python 验收，前端运行 Node 测试及语法检查；离线完整构建后确认资源版本号、源文件不变、无外部资源请求。
- 功能按阶段中文提交；GitHub 存档只包含代码、文档和允许提交的生成物，不自动提交用户上传的 PDF/Word/Excel 原件、数据库、回收站和转换缓存。

## 9. 已采用的默认决策

本方案以方便使用且保持现有部署方式为优先：文件夹就是分组；所有类型采用统一交互；Office 提供只读预览和原件下载；新文献库默认本地管理；根目录文件有入口；永久删除保留二次确认。后续实施若环境无法提供 Office 转换器，将明确交付为“管理与下载可用、Office 预览待部署转换组件”，不会宣称已经支持完整预览。
