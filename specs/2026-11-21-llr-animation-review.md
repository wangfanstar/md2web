# LLR 3D 动画修改与标准核对方案

## 核对范围

本次使用工作区的 UE Specification 1.1 第 5 章文本和实际源码 `docs/html/ref/visual-pcs-assets/pcs-llr-lab.js`，对照提交 `5b82a3b`。核对覆盖下表中列明的规则和实现位置。结论适用于当前教学动画和所列场景。完整 PHY 调度、扩展 CRC4、增强 NACK 及全部组合仍需专项核验。本文为修改方案。

## P0 · 先让仿真状态由事件驱动

| 项目 | 标准依据与源码观察 | 修改与验收 |
|---|---|---|
| TX 与 ACK/NACK 状态 | §5.1.5 图 5-3、§5.1.6–5.1.7 图 5-4。当前 `simulate()` 生成场景步骤，`updateStateOverlays()` 从步骤字段和历史推断状态。 | 为每个端口保存 TX 与 ACK/NACK 状态。INIT_ECHO、NACK 发出、期望帧到达、超时等事件触发转换。四角浮框只读取对应状态。 |
| 序号与接收判定 | §5.1.5、§5.1.7–5.1.8，表 5-10、5-11。当前多数演示使用预设序号 9、10、11。 | 保存 `tx_seq`、`next_rx_seq`、`acked_seq` 和未确认队列。序号按 20 位空间回绕。测试顺序正确、缺失、重复、坏 FCS 和 poisoned FCS，分别记录校验结果和交付结果。 |
| ACK、NACK 与缓冲 | §5.1.5、§5.1.8–5.1.9。当前重放主要复用预设帧步骤。 | 校验反馈序号后释放累计确认的缓冲，从剩余队首重放。重放保留原始序号。模拟反馈丢失后重新收到已交付帧，验证重复检测和缓冲释放。 |
| 重放计数与 Flush | 表 5-10、图 5-3、§5.1.5。当前 `attempt < 3` 是预览限制，`attempt` 也参与上限判断。规范的 `replay_ct` 在离开 REPLAY 且 `nack_received` 为零时递增，有确认进展的 ACK 将其清零，收到 NACK 按规范 SHOULD 清零。定时器到期和 NACK 是不同触发条件。 | 把预览步数与协议计数拆开。单独实现重放、驻留和 PCS 失锁定时器，记录启动、停止、复位及到期事件。验收 NACK、超时、上限 0/255、驻留到期、PCS 恢复与 FLUSH 后重新 INIT。 |
| TX/RX 计数 | §5.1.11 表 5-13。当前计数器由步骤附带字符串累加。表中 `rx_ok` 统计 FCS 正确的 LLR 帧，`rx_expected_seq_good` 还要求序号符合预期。因此一帧可以同时计入 `rx_ok` 和 `rx_missing_seq`，交付结果仍为丢弃。 | 以发送结束、接收分类、反馈收发、REPLAY 退出等事件更新统计。分别断言 `rx_ok`、按序交付和丢弃计数。反馈丢失只增加发送端的对应 CtlOS 计数。 |

## P1 · 补齐信令与错误路径

| 项目 | 修改与验收 |
|---|---|
| CtlOS 编码与插入 | 按表 5-8 保留 INIT、INIT_ECHO、ACK、NACK 的字段级测试。当前 `wireData()` 有字段编码，`simulate()` 用估算反馈时刻。继续依据 §5.1.3.1.1、§5.1.9、表 5-12 与 UE PHY 相关条文核查插入对齐、首个机会、目标间隔和仲裁，在块流时间线上标出实际插入槽。对齐与首个插入位置的具体规则待核。 |
| LLDP | 按 §5.3.2.1.6.1 覆盖双方 TLV 版本、W/E 组合、对端无 TLV 和配置覆盖。协商失败时展示普通以太网路径，成功后进入对应方向的 INIT。 |
| CBFC | 按 §5.2 的 LLR/CBFC 交互规则为新帧、重放及丢弃分别建模。已核实重放阶段禁止再次更新 `S_VC_CC`。继续对照 Type D、接收计数与 `CF_Update` 的条件。与 LLR CtlOS 共存时核查仲裁是否避免饥饿。 |
| 错误注入与接收弹窗 | 注入丢帧、坏 FCS、poisoned FCS、重复及反馈丢失。由 RX 判定生成接收弹窗和统计，显示检测到的状态、序号和是否交付。当前 `openFormat()` 的基础字节样例来自同一发送编码函数。保留它作为明确标注的 TX 参考，并让 RX 使用接收结果。 |

## P2 · 表现与验收

- 丢帧位置取当前视图的链路节点。为首次帧、重放帧、重复帧和坏 FCS 帧使用可辨认样式，并验证三档 3D 视图、正反方向和暂停行为。
- 界面标明合成时序、填充块、固定加扰初态和未建模能力。播放倍率只改变呈现节奏。
- 实施顺序为纯状态模型和边界测试、连接现有 3D 与统计、再做 CtlOS 调度和 CBFC。每组提交附标准条款、输入事件和预期状态及计数的记录。
