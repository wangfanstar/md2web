# md2web 导航、仓库管理、登录权限、缓存与历史对比实现方案

- 日期：2026-10-20。
- 代码基线：`3cb450e0a4c6a9629c73f8395aac95a78774d67d`。
- 状态：**设计方案，尚未实施本轮功能**。
- 范围：面包屑目录链接、仓库重命名、缓存优化、登录记忆、用户管理员授权及 JSON 持久化、双栏修改历史对比。
- 约束：Python 3.6.8、SQLite 3.7.17 兼容；前端原生 JS/CSS；运行时完全离线，无 CDN；认证写接口保留登录、权限及 CSRF 检查。

## 1. 目标及默认解释

| 需求 | 目标行为 |
| --- | --- |
| 文档顶部路径 | 首页、md、仓库、每一级子目录均可点击；文档名表示当前位置 |
| 配置页修改仓库名 | 可修改显示名称，也可明确执行实际仓库文件夹重命名；重命名不改变稳定仓库 ID |
| 访问规模与缓存 | 按约 30 人同时在线优化，减少重复下载和数据库写入；设计压测覆盖 100 人并发短时峰值 |
| 保留登录信息 | 同一浏览器关闭重开、服务重启后，在有效期内继续保持登录 |
| 同 IP 记住用户名 | 以浏览器设备为主、IP 为辅助记忆用户名；登录过期时自动填入该设备上次使用的用户名 |
| 用户权限管理 | 配置页可以将已知用户提升为网站管理员，或撤回授权；权限策略保存到私有 JSON |
| 修改历史 | 提供类似 Beyond Compare 的左右对齐、行内高亮、同步滚动、差异导航和版本选择 |

“最大不超过 1 万”暂按用户/访问规模上界理解，常态容量依据是约 30 人同时在线；不是一万并发承诺。压测报告分别记录用户记录数、在线会话数、请求速率和文档规模，避免把这些指标混为一谈。

本期保持单机 Flask + Waitress + SQLite 架构，优先消除实际重复工作。暂不引入 Redis、分布式会话或新的数据库服务。

30 个活跃页面按现有周期会产生约 `30 × 2 ÷ 3 = 20` 次完整文件请求/秒，还没有计入正文、元数据等请求。索引不变时也反复传输和 JSON 解析，这是优先优化项。

## 3. 面包屑：所有目录可点击

### 3.1 页面行为

例如：

```text
首页 / md / 硬件设计 / 接口规范 / 时序说明
```

| 路径段 | 链接目标 |
| --- | --- |
| 首页 | `index.html` |
| md | `html/index_all.html` |
| 硬件设计 | 映射中 `md/硬件设计` 对应的仓库入口 |
| 接口规范 | 映射中 `md/硬件设计/接口规范` 对应的子目录入口 |
| 时序说明 | 当前文档名称，无链接，保留 `aria-current="page"` |

子目录沿用现有唯一命名，如 `index_硬件设计_接口规范.html`。不能直接拼成 `index_接口规范.html`，因为不同仓库可能都有同名子目录，也可能存在命名清洗或 `-2` 去重后缀。界面展示简短目录名，链接使用构建的真实结果。

### 3.2 实现

1. 构建产出公开导航清单，例如 `html/navigation-map.json`，内容仅含稳定仓库 ID、显示名、目录路径、入口页面和兼容映射。
2. 将同一份数据内嵌为离线可用的 `lib/navigation-data.js`；认证源、用户名、授权策略和凭据不进入这两个产物。
3. `workspace.js` 按路由逐段累积 `md/...` 路径，从映射读取 `href`，不要再次实现命名算法。
4. 静态页链接使用原始 `<a href="html/index_....html">`，遵守 `<base href="../">`；带中文的路径按 URL 规则编码，标签按 HTML 文本转义。
5. 新建/移动/重命名后刷新导航版本，重绘面包屑；找不到映射时显示普通文本，不生成猜测地址。
6. `file://` 使用内嵌数据，不请求接口；HTTP 使用版本信息感知重建。

**验收**：合并页、仓库页、多级子目录页中点击每个祖先目录均正确；覆盖中文、空格、嵌套仓库、同名子目录、去重文件名和 HTTP/file 两种模式。

## 4. 仓库名称与实际目录重命名

### 4.1 两类操作明确区分

配置页每个仓库提供：

- **显示名称**：常用名称，保存后更新总览、侧栏、面包屑、搜索过滤器；不移动文件。
- **文件夹名称 → 重命名**：修改 `docs/md` 下实际挂载目录名，界面预先展示旧路径、新路径、入口地址和影响范围。

现有 `repositories[].id` 作为永久身份保持稳定，继续关联凭据、同步任务和数据库绑定。显示名称使用新增 `displayName`；物理路径继续使用 `mount`。禁止将修改名称实现为“删除旧仓库再创建新仓库”。

入口页兼容规则：新增可选 `entrySlug`，未配置时保持当前 ID 命名；实际目录重命名可以同步生成新名称入口，旧入口保存为离线可用的跳转页，保留 hash 中的文档路径及章节参数。显示名称单独修改不强制改变入口地址。所有入口仍由统一映射分配并去重。

### 4.2 按来源类型处理

| 类型 | 实际重命名行为 |
| --- | --- |
| 本地仓库 | 移动本地挂载目录，同步 SQLite 当前路径和历史 |
| SVN 仓库 | 只修改本站挂载目录/显示名；稳定仓库 ID、远端 URL、UUID 和 SVN 版本保持不变，不执行远端 `svn move` |
| 软链接仓库 | 只重命名链接或目录联接本身；`linkTarget` 不变，不移动目标目录内容 |
| 未配置目录 | 保留来源探测；执行前建立稳定身份或明确绑定，使后续凭据和入口不随名称重新计算 |

### 4.3 接口与事务

拟新增管理员接口 `POST /__admin/repository-rename`：

```json
{
  "repositoryId": "hardware",
  "newName": "硬件资料",
  "expectedMount": "md/硬件设计",
  "expectedConfigVersion": "配置版本号",
  "requestId": "32位幂等操作号"
}
```

必须在服务端执行：

1. 管理员、CSRF、名称、路径、Windows 保留名、大小写碰撞及目标存在检查。
2. 检查仓库内活动草稿、正在运行/结果不确定/已提交待发布的操作和后台同步。存在这些状态时拒绝改名并返回具体阻塞项；尚未执行的 prepared 审阅取消后重新准备，不改写已冻结审阅内容。
3. 按现有锁顺序获取内容锁和数据库锁，记录可恢复的重命名日志。新 JSON 先写临时文件并校验。
4. 更新当前仓库以及被包含的嵌套仓库 `mount`、`folderGroups` 路径、`repo_bindings.mount_path`、已发布文本路径、可迁移的历史路径和当前文档快照。
5. 回收站元数据中的原路径、挂载路径和附件路径一并迁移；软链接仅操作链接本身。
6. 已完成操作的审阅快照、历史审计保持原始内容；另建持久的旧路径→新路径映射，查询历史元数据和打开旧链接时解析。不得全表替换已完成提交的 JSON。
7. 确认数据库、私有 JSON、目录操作完成后，触发站点重建与缓存失效。重建失败返回“名称已修改、页面待重建”的可重试状态，不重复执行文件重命名。
8. 文件或配置确认失败时回滚；如果回滚失败，保留备份和恢复日志并显示具体路径。启动时检测未完成重命名，不自动覆盖用户新文件。

增加 `pathAliases` / `entryAliases` 等持久映射，并限制循环、链长及与现有真实路径的冲突。普通 `PUT /__config` 不允许绕过这个接口直接迁移已有仓库的 mount。

**验收**：改名后凭据不丢、同步仍指向同一远端、历史仍可查、旧链接能打开；模拟配置写失败、数据库失败和重建失败，结果明确且可以恢复。Windows/Linux 分别验证大小写改名与目录联接。

## 5. 缓存和 30 人在线容量优化

### 5.1 HTTP 缓存分类

| 资源 | 拟采用策略 | 更新方式 |
| --- | --- | --- |
| 已校验内容版本的 JS/CSS/字体/第三方库 | `public, max-age=31536000, immutable` | 构建 hash 变化后使用新 URL |
| 无版本静态资源、HTML 入口 | `no-cache` + ETag/Last-Modified | 浏览器条件请求，避免陈旧入口 |
| Markdown、导航清单、搜索索引 | `no-cache` + 内容版本/ETag | 不变化时无需重新传正文；变化时立即获得新内容 |
| 登录、用户权限、配置、草稿、历史和对比接口 | `private, no-store` | 不进入公共浏览器/代理缓存 |
| 公开目录/文档元数据 | 有界进程内缓存；响应版本化 | 本站写操作主动失效，外部变更通过文件签名/短 TTL 兜底 |

注意：不能只看 URL 带 `?v=` 就返回一年缓存。只有 `v` 与服务器当前资源内容版本相符，或资源使用不可变的带 hash 文件名时，才设置 immutable；旧版本请求不能被当成新内容永久缓存。

认证服务和只读预览服务共用缓存分类工具，避免两种服务表现不同。静态私有文件禁止清单优先于缓存判断，真实配置 JSON 仍不可匿名下载。

### 5.2 轻量版本检测

1. 构建最后原子发布 `html/site-version.json`，包含独立的 `buildId`、`searchVersion`、`navigationVersion`、`contentVersion`；不包含用户数据。
2. 活跃页面每 30 秒检查一次小型版本文件；后台标签暂停，重新获得焦点时检查。失败使用 30→60→120 秒退避，恢复后回到正常周期。
3. 取消每轮全量索引下载和 `_sync=Date.now()`。索引版本变化才获取索引；侧栏/导航版本变化才获取对应数据。
4. 本人完成保存、上传、移动、重命名后立即刷新相关数据，不必等轮询；同浏览器标签通过 BroadcastChannel，旧浏览器用 storage 事件通知。
5. 外部改文件仍由现有监听/重建触发版本更新；请求版本与取得的索引不一致时重试一次，避免混用不同构建的导航和索引。

30 个活跃页面在内容无变化时，轻量版本检查平均约 1 次/秒；正文和索引不重复传输。上述数值是调度推算，实际效果由压测记录。

### 5.3 服务端和浏览器内存

- 公开元数据/目录列表采用 LRU + TTL，初始总预算 32 MiB、最多 256 个条目，两个上限同时生效；配置页允许调整。
- 缓存键包括规范路径、仓库 ID、文件/目录版本及影响结果的查询参数；若将来出现用户专属内容，必须增加权限隔离或停止共享缓存。
- 发布/恢复/改名/同步后的失效走统一函数，覆盖目录祖先、导航、搜索及文档元数据；失败回滚不发布新的缓存版本。
- 同一个目录的并发缓存未命中合并计算，缓存命中不重新扫描整库。
- 保留现有 `_touch` 节流，先测量后决定是否调整；权限撤销仍逐请求校验，不为缓存命中而延迟降权。
- 初期不缓存可变登录权限对象。搜索索引可按站点+版本保存在浏览器 IndexedDB，限制总空间并淘汰旧版本；源码、草稿和比较正文默认仅在页面内存中保留。
- 延续 SQLite 兼容模式和短事务；不直接将 `journal_mode` 切到 WAL。慢 SVN、全站构建、差异计算不能长期占据数据库锁。
- 构建请求合并：一次构建进行时，后续修改设置待重建标记，结束后最多追加一轮；发布完成的内容版本不能早于实际落盘的生成物。

### 5.4 验证目标

在记录硬件配置的测试机上执行 30 并发常态、100 并发短峰值、最多 1 万用户记录的混合读写压测。建议目标：静态资源暖缓存 p95 < 100 ms，本地元数据/API p95 < 300 ms，本地单篇保存 p95 < 1 s（不含 SVN 网络和后台重建）。这些是验收目标，不是尚未测量的性能承诺。

同时记录缓存命中率、索引传输字节、扫描次数、锁等待时间、进程内存和错误率；内容未变化时不得持续全量下载索引，内存应受配置上限约束。

## 6. 保持登录与用户名记忆

### 6.1 身份识别规则

**有效会话 Cookie 决定登录身份，IP 只参与用户名提示。** 共享办公网络/NAT 下，多人使用同一个 IP 是正常情况，不以 IP 自动切换或登录到其他账号。

登录弹窗新增“保持登录”和“记住用户名”，并提供“退出登录”“忘记此设备”两个不同操作：前者撤销会话，后者同时清除设备和用户名记忆。

用户名提示优先级：当前有效会话 → 当前站点/认证源的本机用户名记录 → 有效设备标识对应的上次用户名。服务端 IP 辅助记录以“认证源 + 随机设备标识 + IP”为键，同 IP 的其他设备不继承身份。没有设备记录时显示空登录框。

### 6.2 持久会话

- 普通会话保持现有默认 8 小时、闲置 30 分钟；用户勾选“保持登录”时，建议初始绝对有效期 30 天、闲置有效期 7 天，可在配置页修改。
- 数据库增加会话类型/持久标识及身份策略版本；仍只保存随机 token 的哈希。Cookie 使用 HttpOnly、SameSite=Lax、Path=/，HTTPS 部署沿用 Secure 设置。
- 移除“所有合法持久会话必须匹配当前 process_epoch”的要求。普通服务重启恢复未过期持久会话；一次性迁移时不将旧会话自动升级成长会话。
- 持久会话仍校验撤销状态、用户禁用状态、当前认证源和有效权限。退出、改密、管理员强制下线、认证源变更立即失效。
- 认证源未变时，普通配置修改、显示名修改或重建不强制退出；认证源变更只撤销受影响来源会话。
- 重新登录或续期轮换 token；CSRF 在会话恢复时从 `__auth/session` 获取，前端跨标签更新，不能持有过期 CSRF 一直重试。
- SVN 写入沿用现有加密凭据解析；网页登录仍有效但 SVN 口令失效时，提示更新 SVN 凭据，不伪装成整站退出。

新增设备提示记录仅保存用户名、设备 token 哈希、IP 辅助值和更新时间，不保存明文密码或登录 token；按 30 天 TTL 清理。IP 从受信任的直接连接/明确代理配置获取，不盲目信任客户端传入的 X-Forwarded-For。

**验收**：浏览器关闭重开、服务重启、会话过期、手动退出、改密、同 IP 两个账号、IP 改变、认证源切换和共享设备换账号均有测试；不能出现用户名串用导致的自动提权。

## 7. 用户权限管理与 JSON 持久化

### 7.1 配置页 UI

新增“用户与权限”面板，管理员可按用户名搜索和分页查看：认证来源、用户名、显示名、网站权限、是否启用、最后登录时间、当前会话数。支持：

- 提升为管理员、恢复为普通用户。
- 禁用/启用用户、强制退出该用户全部会话。
- 保存到当前 JSON 方案，显示保存结果与配置版本。

被提升用户拥有与现有网站管理员相同的配置、用户管理、同步、反馈管理等网站权限；SVN 服务端 ACL 仍由 SVN 账号决定，网站提权不代表获得远端 SVN 写权限。

### 7.2 认证来源和权限分离

统一使用 `effective_role(user, config)` / `require_admin()`，授权键为“认证源 ID + 用户名”，不能仅用用户名，也不能用换库后会变化的数据库整数 ID。

重要兼容调整：

1. `revoke_svn_sessions` 不能继续通过 `role != admin` 找 SVN 用户；改为认证来源不是 `local-admin`。否则提升后的 SVN 用户会漏掉撤销。
2. SVN 登录成功后的返回值不能固定写 `role:user`，应返回当前有效权限。
3. 前端管理员按钮与 `SiteAuth.isAdmin()` 使用服务端有效权限；服务端仍在每个管理请求重新校验。
4. 本地账号改密与 SVN 身份验证按认证来源区分。SVN 管理员不进入本地密码哈希校验，也不会因提权而变成本地认证账号。
5. 角色变更、用户禁用后，下一个请求立即使用新策略；客户端收到刷新通知更新 UI，不能仅隐藏按钮。

本地恢复管理员保留；禁止通过权限面板/配置导入禁用最后一个可恢复的本地管理员。权限表只允许修改网站权限，不返回密码哈希、可解密凭据或 session token。

### 7.3 JSON 是权限策略来源

权限策略放入已被 Git 忽略、受管理员接口保护的当前 `docs/html/md2web_config*.json`，并随私有方案备份保存。SQLite 保存用户身份、会话、审计和必要的应用状态，不与 JSON 各自维护互相冲突的授权名单。

配置加载、`PUT /__config`、JSON 编辑器保存、方案导入/切换以及专门的用户接口，全部调用同一校验和策略应用服务。不能只在用户管理按钮上校验权限。

采用 `expectedConfigVersion` 防止两个管理员互相覆盖；写临时 JSON → 校验 → 原子替换 → 应用内存策略/撤销所需会话 → 记录审计。失败时保留上一个有效策略，并返回具体失败状态。重启从已确认的 JSON 恢复策略。

授权变更审计记录操作者、目标认证源/用户名、前后角色、时间和来源 IP。审计日志与登录会话不导出到公开配置示例、搜索索引或离线快照。

### 7.4 拟新增接口

| 接口 | 用途 |
| --- | --- |
| `GET /__admin/users?query=&cursor=&limit=50` | 管理员分页查询用户和有效权限 |
| `POST /__admin/users/permission` | 修改某用户角色/启用状态，并保存当前 JSON |
| `POST /__admin/users/revoke-sessions` | 强制下线指定用户 |
| `GET /__auth/login-hint` | 仅根据当前设备标识返回用户名提示，响应 no-store |
| `POST /__auth/forget-device` | 撤销当前设备会话并清除用户名提示记录 |

权限修改/强制下线接口要求管理员和 CSRF；设备清除接口只操作当前设备。现有登录接口扩展 `rememberSession`、`rememberUsername`，仍兼容旧调用参数。

## 8. 修改历史：双栏文本对比

### 8.1 交互布局

```text
修改历史：时序说明.md
来源：[已保存本地版本 / 个人草稿 / SVN 提交记录]
左版本：[较早版本 ▼]  右版本：[当前已保存/当前编辑内容 ▼]
[交换] [上一差异] [下一差异] [仅看差异] [忽略空白] [自动换行]
┌──────────────────────────┬──────────────────────────┐
│ 左侧版本 / 时间 / 作者     │ 右侧版本 / 时间 / 作者     │
│ 行号  原文本，删除高亮     │ 行号  新文本，增加高亮     │
│ 对齐占位，修改行内高亮     │ 对齐占位，修改行内高亮     │
└──────────────────────────┴──────────────────────────┘
差异概览条；新增 N 行 / 删除 M 行 / 修改 K 处
```

两栏按差异块对齐，增加/删除使用占位行保持对应关系；垂直同步滚动，可选横向联动；长文档按对齐行虚拟渲染。默认保留三行上下文，支持展开省略段。

支持任意两个历史版本比较、历史对当前已保存、历史对编辑器未保存内容。最后一种直接读取编辑器内存快照并显示“未保存”，不先保存草稿。

本期是只读比较视图。恢复历史仍使用“载入编辑器 → 人工检查 → 按原模式保存/提交”，不会点击对比行就覆盖文档。保留 unified diff 文本入口和下载功能，方便复制补丁及排查。

### 8.2 版本来源和接口

- 本地版本：复用 `local_document_versions`；历史列表补充作者、基线 hash、分页 cursor。
- 个人草稿：继续按当前用户授权读取 draft/revision，不因全站管理员权限而默认公开其他人的个人草稿。
- SVN 提交记录：复用日志接口，按需取指定 revision 正文；若现有 cat 封装不支持 revision，再扩展统一 SVN 客户端，禁止前端提交任意远端 URL。
- “上一版本”沿用当前语义，列表清楚显示真实来源，不能把个人草稿当成已提交 SVN 版本。

拟增加 `GET /__md/compare?path=...&left=...&right=...`，统一解析 `local:ID`、个人 `draft:ID`、`published`、`svn:rN` 等引用，返回两侧原文、版本标签、时间、作者、hash 和大小。后端必须核对版本所属路径、仓库绑定与读取者权限。旧 `__md/diff` 保持兼容。

版本选择采用显式引用，前端“当前编辑内容”不作为任意路径上传到比较接口；在浏览器将已授权取回的历史文本与当前内存内容比较。

### 8.3 计算、性能与离线依赖

新增本地 `web/diff-view.js`、`.css` 和 `diff-worker.js`，由构建复制到 `docs/lib/`。优先采用独立、可单测的有界行级 Myers 比较，修改块内部再做字符级比较；重运算放 Web Worker，不阻塞编辑器输入。

第一版设定明确的降级阈值：

- 常规文档：每侧不超过 1 MiB / 1 万行，完整行级和行内高亮。
- 较大文档：每侧不超过 5 MiB / 5 万行，按需关闭行内高亮，虚拟渲染。
- 超过阈值或计算预算：保留版本选择、原文读取/下载，提示采用大文件模式；Worker 超时可中断，不能无限占用 CPU。

阈值只限制交互式比较，不改变项目统一的 100 MB 上传限制，也不截断保存的正文。代码块、HTML 和 Markdown 在对比区按纯文本展示，使用 `textContent`，不执行其中脚本。

正常 `file://` 文档阅读仍可用；需要认证数据库的历史列表只在认证服务中提供。对比组件本身加载本地资源，不请求 CDN。

**验收**：空文档、全增/全删、中文、Tab、CRLF、超长行、重复行、代码围栏、同内容不同换行、任意版本对比、未保存内容及大文件降级；“忽略空白”只影响显示，不修改原文。

## 11. 测试、迁移和交付

1. 每阶段先增加能复现目标行为/异常边界的失败测试，再实现；Python 验收统一使用 3.6.8，包含 Python36CompatibilityTests 和 SQLite 兼容检查。
2. 数据库按执行时最新 schema 增量迁移，不写死可能被其他功能占用的迁移版本；迁移前使用项目现有备份机制。
3. 覆盖角色修改通过普通 API、JSON 编辑、导入、方案切换四种入口；匿名请求和普通用户不能通过直接改参数获得管理权限。
4. 缓存测试覆盖 ETag/304、版本不匹配、重建后刷新、后台标签恢复、缓存超限、会话内容不被公共缓存，以及外部文件变化。
5. 浏览器测试使用独立 fixture，不依赖用户临时文档；验证中文路径、多标签、持久会话、导航回退及比较滚动。
6. 压测只针对隔离测试数据，不向真实 SVN 提交；SVN 功能另外使用测试库验收，报告分别列出本地性能和网络等待。
7. 修改 `web/` 后由构建同步生成物，构建不修改 `docs/md/`；真实用户、凭据、权限名单和会话不提交公开仓库。
8. 交付包括代码、迁移、回归/浏览器测试、压测记录、配置字段说明及更新后的操作文档。按阶段提交中文 Git 信息，便于定位和回滚。

本方案采用的默认决定是：支持显示名和实际目录名两种修改；稳定仓库 ID 不变；目录入口复用真实生成映射；持久登录依赖 Cookie 会话，IP 仅辅助记住用户名；网站管理员权限不改变 SVN 服务端授权；对比视图以只读双栏为主。这些决定在实施前均可直接在本文调整。
