# 多行公式显示修复

问题：编辑器先调用 Markdown 解析器，再运行 KaTeX。`$$` 内的空行被拆成段落，`\_` 等 TeX 转义被 Markdown 消耗，导致公式失去完整性。阅读页也存在同一问题。

修复：`MathRender.prepare` 在 Markdown 解析前保护完整公式，解析后以 HTML 转义文本还原，再交给 KaTeX。编辑器和阅读页共用此逻辑；跳过代码围栏、行内代码和转义美元符号，不改写文档源文件，也不自动猜测未知命令的含义。

用户示例中的 `\leg` 是无效命令；若要表示小于等于，应使用 `\leq`：

```latex
$$
\text{S\_VC\_CU}[x]+\text{pktCredits}
\leq

\text{S\_VC\_CL}[x]
$$
```

回归覆盖多行空行、文本下划线、四种分隔符、代码区、未知命令、HTML 转义及属性安全。真实 Edge 浏览器验证编辑器与阅读页渲染路径。

## 截图反馈后的补查

用户截图已经使用正确的 `\leq`，仍显示红色源码。本机用完整生成页面（包含 DOMPurify 和全部站点脚本）测试截图中的两段公式，均能正常显示。这不能证明用户当前服务器已加载最新代码。

发现并复现另一条失败路径：部署服务器可能保留本机不存在的仓库入口页；只更新 Git 中的脚本并不会更新这些入口页里的资源版本号。旧版本 URL 的 immutable 缓存会使浏览器继续使用旧的公式解析脚本。

认证服务和只读预览现在在响应生成入口页时，按实际本地 JS/CSS 内容更新版本号，不修改入口文件或仓库目录。认证服务不再使用仅代表 HTML 文件的过期条件响应；预览服务的 HTML ETag 由更新资源版本后的响应内容计算，脚本变化不会误返回 304。其他静态资源继续保留原有缓存策略。

`tests/test_asset_refresh.py` 覆盖资源版本刷新、服务器独有入口页和预览条件请求；`tests/browser/site-math.cjs` 连接真实认证服务，使用故意保留旧版本号的完整入口页验证两段公式。单独编辑器测试也补上 DOMPurify。

部署时需更新代码并重启 Python 服务，然后重新打开或刷新文档页面。对于纯静态托管或 file:// 页面，仍需在部署目录重新离线构建以更新当地仓库入口页。当前没有用户服务器地址，尚未直接验证其实际运行页面。
