# 重启后按钮未更新与登录状态失真修复

## 已复现的代码问题

服务启动只检查文档索引和 Markdown 变化，没有同步 web 源码与 docs/lib 的差异。服务器仅更新源码或保留旧前端产物时，即使重启也可能继续提供旧脚本。之前的 HTML 资源版本刷新只能反映 docs/lib 的内容，不能代替前端产物更新。

登录状态在会话校验请求失败时只修改 available，保留旧 authenticated/user/CSRF；页面长时间打开时没有定期校验。旧会话响应还可能晚于退出请求到达并覆盖界面。反馈页另外维护一份登录状态，未随公共登录状态更新。

## 修改

- 默认站点启动前，对比 web 下 JS/CSS 与 docs/lib，原子替换发生变化的文件并保留文件权限。此步骤与文档重建分开，使用 --no-build 也会同步前端。自定义只读预览目录不受影响。启动日志列出更新文件，同步失败明确提示写权限问题。
- 不重写仓库入口页、索引或 docs/md，不用本机构建清单覆盖服务器仓库。既有服务的 HTML 资源版本刷新机制随即使用新脚本摘要。
- 「复制本页内容」改为公共页面工具，不再受仅具体 Markdown 文档显示编辑工具的路由限制。
- 会话查询显式不缓存；校验失败、超时或匿名响应时，清掉用户名、角色、CSRF、编辑权限和私有 AI 默认值。
- 每 30 秒对可见页面复核会话，回到页面、重新聚焦或切换路由时复核。并发校验共用请求，10 秒超时后不能继续显示旧登录状态。
- 登录需验证 Cookie 对应的真实会话后才报告成功；通过请求代次隔离旧响应，避免覆盖退出或新登录。旧写请求的 401 不取消正在进行的新登录。
- 编辑器、设置、文件夹操作和反馈接口收到 401/403 时同步校验状态；401 立即清掉旧登录显示，不自动重放写操作。反馈界面与公共登录状态保持一致。
- 保留现有会话政策：「保持登录」的有效会话可跨重启；普通会话按现有政策失效后，应重新登录。失效不清掉编辑器尚未保存的文字。

## 验证与部署范围

Python 3.6.8 专项验证过期产物同步、启动 --no-build、自定义预览目录隔离、源文档与服务器独有入口保持原样。Node 覆盖网络失败、超时、匿名权限清理、迟到响应、登录 Cookie 校验、并发复核和旧 401 与新登录竞争。

真实 Edge 连接隔离认证服务，模拟旧产物及会话重启，验证复制按钮、普通/持久会话、断网恢复、写请求 401 与未保存文字保留；另回归配置六 Tab 和保留格式复制。全程使用测试文档与账号，没有直接登录或修改用户的 Linux 服务器。

验证记录：Node 全量 137 项通过；首次 Python 3.6.8 全量中，原有文档读写测试遇到一次 Windows 临时文件原子替换拒绝访问，单项重跑及启动同步专项共 4 项通过；随后全量 579 项通过（跳过 1 项）。该文件写入实现不在本次修改范围。严格离线构建及前端语法检查通过。

部署需拉取本次代码并重启原有 Python 服务，再刷新浏览器页面。只更新服务端源码而不重新启动，无法让已运行的旧 Python 进程获得此次启动与会话修复。
