# UE 1.1 LLR 仿真用例与覆盖方案

## 运行基线

以 UE Specification 1.1 第 5 章为协议依据。协商见 §5.3.2.1.6.1，数据与控制编码见表 5-1、5-2、5-8，TX、接收判定、反馈处理见 §5.1.5–5.1.9、图 5-3/5-4，统计见表 5-13，联合信用处理见 §5.2.9。本文件定义待执行的用例与判据；执行报告单独记录版本、输入轨迹和结果。

默认 A 发、B 收，另跑方向互换。除协商、初始化用例外，初态为已握手、TX=ADVANCE、反馈机=SEND_ACKS、tx_seq=next_rx_seq=10、acked_seq=9、缓冲空、统计清零。使用两帧各 512 B、窗口容纳两帧，正常反馈先于重放超时到达。长度、延迟和注入时刻为测试输入。每步记录协议时间、端口、方向、事件、序号、FCS、交付、缓冲队列、定时器、两端状态及计数增量。单步、快放和倒查同一事件应得到相同快照。

## 常用路径与故障注入

| 用例 | 操作 | 验收判据 |
|---|---|---|
| N01 协商成功 | 双方 W=3，遍历 v0/v0、v0/v1、v1/v0、v1/v1，延迟第二端启用通告 | v0 发布 E=1，v1 发布 E=3；观察对端有效启用后才启动对应 LLR 流程 |
| N02 协商失败 | 分别缺少 UE TLV、本地 W=0、对端 W=0；向接收器注入保留 W=1/2 | 保持普通以太网，E 清零，无 INIT。保留值仅作负向输入 |
| I01 初始化 | 发送 INIT，再回传匹配 ECHO；分别丢首个 INIT、首个 ECHO、注入序号不匹配的 ECHO | 有效 INIT 设置 RX 期望值；ECHO 回送 init_seq/init_data；有效回显前保持 INIT。重发间隔核对 §5.1.9.1.1 |
| I02 两端独立 | 并行初始化两个方向，仅丢 B→A 方向某次回显 | 分别检查两个 TX 和两个反馈机。成功方向可以推进，故障方向继续等待 |
| D01 正常累计确认 | 发送 10、11，B 顺序接收后回 ACK(11) | 交付两次，期望 12；返回前缓冲 [10,11]，返回后为空。A.tx_ok=2，B.rx_ok=B.rx_expected_seq_good=2，A.tx_replay=0 |
| D02 头帧丢失 | 丢 10，送达 11 | B 保持期望 10，11 的 GOOD FCS 计入 rx_ok，同时计入 rx_missing_seq。B 发送 NACK(9)，进入 NACK_SENT |
| D03 中间或尾帧丢失 | 分别发送 10–12 丢 11、只发送 10 丢 10 | 前者由后续帧揭示缺口；后者没有后续序号证据，靠发送端超时恢复 |
| D04 坏 FCS | 在链路损坏帧 10，再重放正确副本 | 首次 B.rx_bad 和 rx_expected_seq_bad 各加一，期望保持 10，反馈 NACK(9)；重放成功只交付一次 |
| D05 Poisoned FCS | 帧 10 按序到达并带 poisoned FCS | B 标记 frame_bad，推进至 11；rx_poisoned 与 rx_expected_seq_poisoned 各加一，单凭 poisoned 状态不触发 NACK |
| D06 重复帧 | 已接收 10，再送达 10 | rx_duplicate_seq 加一，期望保持 11，交付次数保持一次；依图 5-4 区分 duplicate 与 missing 的反馈触发条件 |
| R01 部分确认 | 队列 [10,11,12]，注入有效 NACK(10) | 释放 10，当前发送帧完成后依次重放 11、12；重放沿用原序号和内容 |
| R02 ACK 丢失 | B 接收两帧，丢 ACK(11)，允许后续反馈到达 | B.tx_ack_ctl_os 增加，丢失那次 A.rx_ack_ctl_os 无增量；重放副本按重复检测，最终有效 ACK 清空队列 |
| R03 NACK 丢失 | D02 中丢 NACK(9) | A 的接收 NACK 计数无增量；超时后从 10 重放。B 在 NACK_SENT 期间抑制后续 ACK/NACK，收到期望正确帧后恢复 |
| R04 重放中反馈 | 在重放首帧之前、首帧结束后、末帧结束时分别注入 ACK 或 NACK | 检查已确认前缀、剩余队列、nack_received、REPLAY 退出事件。tx_replay 按退出 REPLAY 次数统计 |
| F01 初始化和冲刷期间来帧 | INIT、FLUSH 各遍历 DISCARD/BLOCK/BEST_EFFORT，并在 FLUSH 后切换 re_init_on_discard | 分别观察丢弃与 tx_discard、上层阻塞、普通帧发送；清空未确认缓冲，按策略重新初始化或等待管理介入 |

## 极值与交叉遍历

| 用例族 | 输入生成 | 必查结果 |
|---|---|---|
| B01 序号回绕 | 从 0xFFFFE 发送三帧；让 ACK/NACK 跨越 0xFFFFF→0 | 窗口按发送顺序释放，所有比较使用 20 位模运算 |
| B02 RX 分类 | 固定期望 E，注入 (E+d) mod 2²⁰；d 取 0、1、−1、524287、524288、524289。每项交叉 GOOD/BAD/POISONED 和 next_rx_seq_vld 真/假 | 独立按表 5-11 计算 expected、duplicate、missing。半空间边界单独断言；只有有效、按序且 GOOD/POISONED 才推进 |
| B03 反馈有效性 | 空队列、单帧、跨回绕队列；分别返回已确认序号、队首、中间、队尾、过期或超前序号 | 按 §5.1.8 两个模差条件判定；非法 ACK/NACK 增加 rx_ack_nack_seq_error，逐项核对缓冲和状态机的后续动作 |
| B04 窗口与空间 | outstanding_seq_max 取 0、1、实现上限及非法上限+1；outstanding_data 取门限−1、相等、门限+1；整帧存储余量取帧长−1、相等、+1 | 分别验证未确认字节门限、序号跨度、真实存储空间三项准入条件。缓冲不足整帧时阻塞，禁止截断 |
| B05 重放时间 | replay_timer_max 取 0、1、65535 ns；反馈在到期前一拍、同拍、后一拍到达 | 从帧结束触发定时；确认有进展则复位，空窗口停表。记录同拍仲裁规则并验证一次事件只处理一次 |
| B06 重放上限 | replay_ct_max 取 0、1、2、254、255；连续丢反馈，中途分别插入有效 ACK、有进展的 NACK | 对照表 5-10 的计数增量与清零条件。有限上限在规定超时条件下 FLUSH；255 屏蔽次数上限。测试可跳过无事件时间以跑满 254 次 |
| B07 驻留与失锁 | 空/非空缓冲、PCS 瞬时失锁/持续失锁；恢复分别在到期前、同拍、后；失锁与驻留、重放同时到期 | 检查各自启动、停止、复位及 FLUSH 条件。空窗口仍覆盖持续 PCS 失锁。驻留期间的部分确认重新计时 |
| B08 CtlOS 插入 | 扫 8 B 边界、帧头 256 B 前后、同帧两次插入相隔 2 KB 前后；目标间隔取 400、2048、16384 B；INIT_ECHO/INIT/ACK/NACK 同时待发 | 逐槽输出候选、延后原因和最终偏移。核对表 5-12 优先级、ACK/NACK 发送频率及 NACK_SENT 例外；发送与到达分别计数 |
| B09 CBFC 联合 | 表 5-26 的 A/B/C/D 类型 × 首发/重放 × 正常/丢弃窗口；在窗口内注入 CF_Update 和 CC_Update | 非法配置单独报告。Type D 首发扣信用，重放不重复扣；丢弃不增接收信用。分别核查两类更新的接收规则及仲裁饥饿 |
| B10 复位与双向并发 | 双方并发发包；仅一侧丢帧；在 INIT、ADVANCE、REPLAY、FLUSH 中复位或关闭模式 | 按端口与方向独立核对状态、序号有效位、缓冲和计数，禁止旧定时事件作用于新会话 |

## 执行与交付

1. 首轮执行 N01、I01、D01–D06、R01–R03、F01。以 D01 建立逐事件基线，依次只改变一个注入点。
2. 对 B02、B03、B06 做模型级参数化遍历；B05/B07 的同拍用例记录硬件采样与优先级假设。其余变量做两两组合，方向与每个用例交叉。长时重复运行固定随机种子，保存最短失败轨迹。
3. 每例产出初态、注入表、预期/实际轨迹、终态、失败事件编号。比对合法状态转换、无重复交付、累计确认后释放、重放原序号、各端计数。UI 再复查四角状态、活动方向、字节浮框、RX 丢弃详情及统计跳转。
4. 现有 3D 预设可承载正常发包、坏 FCS、丢帧、反馈持续丢失、初始化、回绕等代表路径。任意原始帧/反馈注入、帧内 CtlOS 仲裁、精确同拍以及完整 CBFC 信用流需要模型测试入口。教学时间尺度、事件预览上限和设备可选能力应写入每次报告。
