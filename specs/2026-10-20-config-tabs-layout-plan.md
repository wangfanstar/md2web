# md2web 配置页多 Tab 布局方案

- 日期：2026-10-20。
- 检查基线：`68207ca`；依据 `web/md2web_config.html`、`web/md2web-config.js` 及对应服务端接口。
- 状态：已实施；实现与验证见 2026-10-21-config-tabs-implementation-review.md。
- 目标：让管理员快速完成仓库配置、排查同步异常、管理账号权限，并清楚知道哪些修改已生效。
- 保持现有技术约束：原生 JS/CSS、本地资源、Python 3.6.8、认证与 CSRF、私有 JSON 配置方案。

## 1. 推荐结论

采用 **6 个主 Tab + 仓库详情侧栏 + 全局待保存栏**：

```text
仓库管理 │ 账号与权限 │ 备份与恢复 │ AI 设置 │ 缓存与性能 │ 配置方案
```

默认进入“仓库管理”。第一次进入且尚未完成 SVN 配置时，在仓库页给出短引导，直接链接到所需设置；不把认证表单和整段使用说明堆到仓库表格上方。

页面标题改为“站点管理”。“仓库配置”作为仓库 Tab 的内容标题，避免用户误以为用户权限、AI 和备份也属于某一个仓库。

这套方案按用户实际任务划分入口：管理资料来源、处理身份与授权、维护备份、设置 AI、调整性能、管理配置方案。仓库页承担日常工作，低频操作有固定位置。

### 为什么选择 6 个 Tab

| 候选布局 | 判断 |
| --- | --- |
| 3–4 个大 Tab | SVN 凭据、用户授权、缓存和 JSON 仍需挤在一起，长页面问题只是被搬到 Tab 里面 |
| 每个现有面板单独一个 Tab | “账号切换”“认证路径”“默认凭据”“用户权限”“登录策略”等入口过碎，用户需要记住实现细节 |
| 6 个任务 Tab | 可以保留清楚的任务边界；桌面端一行容纳，窄屏可以横向滚动 |
| 默认增加一个总览仪表盘 | 当前核心任务是设置与维护；另做总览会重复展示仓库状态，并增加一次进入仓库的点击 |

不以未验证的使用频率百分比作为依据。实施后可通过任务测试检查是否需要调整顺序。

## 2. 当前混乱的具体原因

1. **信息密度失衡**：仓库表有 8 列，名称列又塞入显示名、实际文件夹名、删除和重命名；明细继续展开地址、口令、频率、权限和维护操作。
2. **配置与观察混排**：入口链接、统计大小、最后更新时间，与输入框和危险操作占据相同层级。
3. **全局设置重复出现**：SVN 认证路径在两个面板可编辑，虽有联动，用户仍容易理解成两个独立配置。
4. **保存边界不明确**：全局保存按钮重复出现；凭据保存、用户提权、同步、重命名等又通过独立接口立即执行。
5. **结果离操作太远**：`setStatus()` 主要写入仓库区域和配置方案区域；在页面下方操作时，结果可能出现在屏幕外。
6. **功能位置不稳定**：用户权限与登录缓存区域由 JS 动态追加；AI、回收站及主面板还有不同的显隐规则。
7. **说明过长且部分过时**：页面仍有“勾选配置 SVN”的表述，实际已是三种来源选择；软链接“强制只读”、SVN 账号“一定是普通用户”等描述也不符合当前能力。

仅给现有 section 加隐藏/显示，无法解决宽表、保存范围和操作反馈问题。因此要同时调整信息层级与状态管理。

## 3. 页面整体结构

```text
┌────────────────────────────────────────────────────────────────────┐
│ 站点管理       [返回首页]                  当前账号：张三 · 管理员 ▾ │
│ 当前配置：主配置 · 已保存                         [管理配置方案 →] │
├────────────────────────────────────────────────────────────────────┤
│ 仓库管理  账号与权限  备份与恢复  AI 设置  缓存与性能  配置方案      │
├────────────────────────────────────────────────────────────────────┤
│ 当前 Tab 标题                 一句用途说明             本页操作区 │
│                                                                    │
│                         当前任务内容                               │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 待保存：仓库管理 2 项、AI 设置 1 项    [查看修改] [放弃修改] [保存] │
└────────────────────────────────────────────────────────────────────┘
```

### 固定区域

- 顶部保留站点管理标题、返回首页、当前账号和当前配置方案名称。
- 账号菜单统一提供登录、退出、切换账号及适用的本地改密入口；不在每个 Tab 重复登录表单。
- 顶部只显示当前方案摘要；选择方案、复制、恢复及 JSON 编辑均进入“配置方案”。
- Tab 导航滚动到顶部后保持可见；避免标题区、Tab、工具条和表头同时大面积固定。
- 底部待保存栏仅在有配置修改或正在保存时出现。移动端同时考虑安全区域，内容底部预留空间。

### 导航与链接

- 默认路由：`#tab=repositories`。
- 可定位到具体任务，例如 `#tab=accounts&section=default-credential`。
- 仓库详情：`#tab=repositories&repo=<稳定ID>`；未配置文件夹使用编码后的 mount 定位。
- 兼容已有 `#repositories`、`#repository-trash`、`#admin-login`，转换到相应 Tab、区域或登录弹窗。
- 刷新、前进、后退恢复正确 Tab；已有脏表单不因路由渲染而丢失。
- URL 只存导航标识，不存用户名口令、Key 或表单正文。

## 4. Tab 1：仓库管理

### 4.1 默认展示

```text
仓库管理                       [刷新信息] [检查状态] [+ 添加仓库]
全部 12 · 正常 9 · 异常 2 · 未配置 1
[搜索名称或路径……] [来源：全部 ▾] [分组：全部 ▾] [状态：全部 ▾]

仓库名称 / 路径    来源      分组      状态      最近更新     大小   操作
接口资料          SVN       硬件      正常      10-20 14:30  28MB   编辑 ⋯
md/interface
会议资料          本地      项目      待配置    10-19 09:00   3MB   配置 ⋯
```

- 默认保留“名称/路径、来源、分组、状态、更新时间、大小、操作”7 列。
- 显示名称是主要文本，实际目录作为第二行等宽辅助文本；点击名称打开仓库入口，点击“编辑”打开详情。
- 不直接在列表中摆放文本输入框、密码框和来源下拉框。
- 同步频率、当前版本、上次检查与错误详情移入仓库详情；列表状态显示最有用的结论。
- 大小和时间使用短格式，悬停或详情显示完整值；统计失败显示“读取失败”，不伪装成 0。
- 保留空文件夹、未配置目录及失效软链接的明确状态。运行时目录发现不能因切换 Tab 被替换为本机构建快照。
- “立即同步全部 SVN”放在批量操作区，不与“保存配置”挤在同一排；执行前显示目标数量。
- “检查状态”仅检查，不隐含修复或拉取。只在状态需要时突出“处理异常”入口。

### 4.2 仓库详情侧栏

桌面端侧栏宽约 520–640 px，覆盖在列表右侧。保留列表搜索条件、滚动位置及选中行；不要展开所有仓库明细。

详情依次排列：

1. **仓库名称与状态**：名称、入口链接、当前配置/实际目录状态。
2. **基本设置**：显示名称、分组、来源类型、允许在线修改/允许合入 SVN。
3. **来源设置**：按下表显示对应字段。
4. **运行状态**：最近同步、更新时间、版本、错误原因；不与可编辑字段混排。
5. **高级与维护**：稳定 ID、实际目录重命名、移除映射、链接维护、修复、删除重建、删除仓库。

| 来源 | 默认显示字段 | 行为 |
| --- | --- | --- |
| SVN 库 | SVN URL、自动同步间隔、同步凭据来源 | 默认显示“使用全站默认账号”；选择“此仓库专用”才显示账号和密码 |
| 本地文件夹 | 分组、编辑权限、目录摘要 | 不显示 SVN 地址、频率及凭据 |
| 软链接 | 目标目录、链接状态、编辑权限 | 默认只读；开启可写时就近解释会直接修改目标目录 |

同步间隔对用户优先显示“跟随默认 / 不自动同步 / 自定义”，自定义再填数值与单位，避免用户记忆“空值”和“0”的含义。

“显示名称”是普通待保存配置；“实际文件夹重命名”是独立立即操作，两者必须分开。稳定仓库 ID 只读，默认折叠，不随显示名变化。

侧栏底部“完成编辑”表示返回列表并保留待保存内容，**不能写成“保存”而实际只改浏览器内存**。旁边显示“待全局保存”。

新建仓库采用同一详情组件：名称/目录 → 来源与必填项 → 权限与保存摘要。没有填写完成时不能触发拉取。需要先保存配置再创建拉取时，使用明确的“保存并创建/拉取”动作，并列出影响范围。

### 4.3 异常处理与危险操作

- 状态卡给出“原因—建议动作”，例如“认证失败 → 检查使用的同步账号”。
- `修复`、`删除重建`、`移除映射`、`删除仓库`不得只靠颜色区分；显示作用对象和结果。
- 删除/重命名前显示旧目录、新目录或回收位置；有待保存修改时先处理，不能以一句提示直接丢弃。
- 回收站入口链接到“备份与恢复 → 仓库回收站”，不在仓库表格下面再追加一个长面板。

## 5. Tab 2：账号与权限

本 Tab 内使用**小型页内锚点导航**，依次为“登录认证、同步账号、用户权限、登录策略”。不再嵌套一排主样式 Tab。

### 5.1 登录认证

- 当前网站登录身份、认证来源、有效网站权限以摘要展示。
- SVN 登录认证路径仅保留一个编辑位置，旁边是“测试路径”。
- “验证一个 SVN 账号”放在可展开的测试区域；明确验证不会切换当前身份。
- 当前账号切换放入顶部账号菜单；若保留“验证并切换”，执行前说明会改变当前身份并按目标账号有效权限更新界面。
- 修改认证路径时说明将撤销相关 SVN 会话，本地恢复管理员可继续管理。

### 5.2 同步账号

- 默认同步账号独立卡片：当前账号、凭据状态、修改入口。
- 密码默认遮蔽；编辑现有配置时不能把展示占位符当成真实密码提交。沿用当前私有 JSON 持久化约定。
- 操作名称使用“验证并保存默认账号”，明确其立即写入；结果在卡片内展示。
- 仓库详情、备份配置中只显示“跟随默认/使用专用账号”及跳转链接；全站默认口令只有这一处编辑。
- 展示凭据优先级：仓库专用 → 全站默认 → 服务端兼容回退。环境变量属于部署信息，折叠到高级说明。

### 5.3 用户权限

使用可分页表格：用户名、认证来源、网站角色、启用状态、最近登录、有效会话摘要、操作。

- 默认自动加载第一页；支持搜索、角色与启用状态筛选。前端分页与服务端实际支持范围保持一致，不能把一页数据的筛选描述成全量筛选。
- 每个用户通过“调整权限”打开小对话框，选择普通用户/管理员及启用状态；确认后立即生效。
- “强制退出”单独操作，不能与保存表单混成一个按钮。
- 本地恢复管理员受保护；网站管理员权限与 SVN 服务端权限分别说明。
- 当前用户降权/禁用后及时刷新可见界面。不能只在下一次进入页面时才隐藏管理功能。

### 5.4 登录策略

集中放置保持登录天数、闲置有效天数；设备用户名记忆等未形成普通表单的字段继续放在高级 JSON，不因重排布局自动扩充设置范围。

“本地管理员修改密码”可复用已有后端接口接入此区域；若本轮仅做布局，则先保留到现有账号设置的跳转。不能让 SVN 管理员误进入本地口令修改流程。

## 6. Tab 3：备份与恢复

固定两个区域，使用页内锚点跳转：

**网站 SVN 备份**

- 顶部展示启用状态、最近结果、目标地址摘要及“立即备份”。当前接口没有提供的统计不编造数值，显示为未提供或后续扩展。
- 配置区：启用、目标 URL、备份频率、提交说明；默认跟随全站同步账号，可切换专用账号。
- 备份范围从实际配置读取并展示。仅备份 `docs/` 时必须说明该范围；不能标称“已完整备份账号、数据库及全部配置”。
- 检查状态位于普通操作区；修复、删除重建工作副本放入“高级维护”。

**仓库回收站**

- 按仓库名称、原路径、删除时间列出条目及恢复入口。
- 恢复前明确同名路径/ID 冲突的处理；仅提供后端已有的能力，不添加尚不存在的“任意恢复版本”或“一键灾难恢复”。
- “恢复配置上一版”只放在配置方案 Tab；此处提供链接，避免用户混淆资料恢复与设置恢复。

## 7. Tab 4：AI 设置

标题“全站 AI 默认设置”，用一句话说明已登录用户可使用默认值，个人设置可以覆盖。

- 基本设置：服务商、API 地址、模型。
- 凭据：默认 API Key，遮蔽展示，显式修改。
- 高级设置：代理策略、上下文字符数、默认资料路径，默认折叠。
- 改动加入全局待保存项；不重复放“保存配置并重建站点”按钮。
- 本轮不新增“测试模型”承诺；如果后续增加，应独立说明请求可能消耗配额，并有真实的服务端校验与超时行为。

## 8. Tab 5：缓存与性能

按“普通设置 + 高级限制”两层展示，数值配单位和当前值：

| 普通设置 | 高级设置 |
| --- | --- |
| 元数据缓存有效期：秒 | 最大条目数：项 |
| 版本检查周期：秒 | 最大缓存容量：MiB；保存时转换成字节 |

展示推荐初值：60 秒、30 秒、256 项、32 MiB。明确这是参数初值，不把它们写成未经测量的容量保证。

实施前核对字段是否真正被消费：当前 `custom-search.js` 的版本检查周期及退避存在固定数值；服务端缓存实例也在应用初始化时创建。若配置字段尚未支持热应用，应补接配置、或明确提示“重启后生效”，不能仅保存 JSON 后显示“已生效”。

不展示虚构的实时命中率、内存曲线或“一键优化”。这些指标需要后端真实提供后再设计。

## 9. Tab 6：配置方案

将其定位为低频的全站管理任务，而不是所有配置前的必经表单。

### 常规区

方案列表显示：名称、当前使用标记、是否有上一版；提供“查看”“复制为新方案”“应用为当前方案”“恢复上一版”。

- 选择下拉项或点击“查看”只预览，不能立即改变运行配置。
- “应用方案”明确立即影响全站并更新默认方案；在确认框展示变化摘要。
- 有待保存表单时，提供“保存后继续 / 放弃修改后继续 / 取消”；默认不丢弃。
- 复制操作默认复制已保存配置；如果支持复制未保存修改，必须另起明确动作。
- 方案恢复是配置恢复，不声称还原源文档目录或 SVN 远端内容。

### 高级 JSON 区

默认折叠，展开后分为“读取、编辑、检查、应用”流程：

1. 显示当前方案与读取版本；明确包含私有凭据。
2. 进入 JSON 编辑时，其他普通表单保持可查看但禁止同时修改。
3. JSON 校验错误在编辑器附近显示行号/具体字段；不直接吞成“保存失败”。
4. 应用前比较已保存基线并展示修改范围；使用配置版本防止覆盖另一管理员的修改。
5. 成功后刷新统一表单状态；失败时保留用户编辑内容。

双向同步普通表单与任意 JSON 文本的复杂度较高。第一版采用互斥编辑模式，避免两份未保存状态互相覆盖。

## 10. 统一保存与即时操作规则

这是布局改造的核心：用户需要随时知道“我改了什么、是否已保存、会影响哪里”。

### 10.1 三种操作状态

| 类型 | 示例 | 展示与保存规则 |
| --- | --- | --- |
| 待保存配置 | 显示名称、分组、来源字段、同步间隔、AI、备份计划、缓存参数 | 加入全局配置草稿，切换 Tab 保留；底部统一保存 |
| 立即写入的设置 | 默认/专用凭据、用户权限、强制退出、仓库重命名、配置方案应用 | 按钮名称说明“保存/应用/执行”；局部反馈；不再计为待保存 |
| 使用已保存配置执行的任务 | 检查、同步、备份、修复、创建链接 | 说明使用当前已保存参数；相关字段有未保存修改时先处理再执行 |

特殊情况必须明确：开启某个备份计划的表单修改尚未保存时，不能点击“立即备份”后悄悄按旧地址运行；默认凭据使用的认证路径被修改但未保存时，也不能悄悄用旧路径验证。

### 10.2 全局待保存栏

- 显示按 Tab 分组的变更摘要，例如“仓库 2 项、AI 1 项”。计数规则按可理解的字段/对象统一，避免输入一个字符就加一项。
- “查看修改”展示字段、旧值、新值；密码和 Key 只显示“已修改”，不能输出到日志或公开页面。
- “保存全部修改”提交统一草稿，并显示目标方案名称；不用“保存当前 Tab”制造多个配置基线。
- “放弃修改”恢复到最近成功读取/保存的基线；仅有实际改动时要求确认。
- 保存分为“写入配置”和“更新站点页面”两个结果。配置已写入但重建失败时，应显示“配置已保存，页面更新失败”，提供重试；不提示用户重复修改并覆盖。
- 当前后端可能对所有配置变更触发重建；第一阶段保留这种行为，但显示真实结果。按字段减少重建可列为后续独立优化。

### 10.3 并发与切换

- 一个中央草稿模型保存隐藏 Tab 的修改，不从当前可见 DOM 拼出全站配置。
- 已加载数据与草稿分离；刷新仓库统计、状态轮询、重新认证不应重建并覆盖脏表单。
- 即时接口若会改变同一配置，应先处理待保存修改，或带版本合并并返回新基线；第一版推荐明确处理草稿后执行，降低覆盖风险。
- 收到 409 后保留草稿，提供“读取最新并比较”，不能自动重试旧配置。
- 切换 Tab、展开说明无需确认。离开整个页面、切换账号/方案、执行会重载配置的操作才检查未保存内容。

## 11. 反馈、加载与权限

### 操作反馈

- 表单校验紧邻字段，顶部汇总可以跳到首个错误字段及所属 Tab。
- 用户提权、凭据保存、同步等即时操作在当前卡片/行显示进度和结果；不能跳回仓库 Tab 才看到。
- 全局保存结果放在待保存栏；Toast 仅作补充，错误不能几秒后消失。
- 多仓库检查/同步逐项显示结果，保留失败对象及重试入口；不要拼成一条过长的状态文本。
- 请求中只锁定相关动作与受影响字段；避免整页长时间不能切换查看信息。

### 加载策略

- 首屏加载会话、公开目录及当前配置必要信息。
- 用户列表、回收站、备份状态、JSON 原文在进入相应区域时按需加载。
- 不再打开页面就扫描全部仓库并发起完整健康检查；显示最近结果与检查时间，用户主动检查，运行中的任务继续更新。
- Tab 内容首次加载后复用，不反复销毁 DOM；后台请求返回时核对配置/账号版本，避免旧响应覆盖新视图。

### 身份状态

| 身份 | 页面表现 |
| --- | --- |
| 未登录或普通用户 | 保留公开仓库的只读列表与登录入口；隐藏凭据、用户权限、私有方案及敏感设置 |
| 网站管理员 | 显示全部管理 Tab；当前身份按有效角色判断，包含被授权的 SVN 管理员 |
| 会话过期/降权 | 立即隐藏并清理敏感视图；阻止继续写入；提示登录或权限变化。未保存的非敏感修改仅在当前内存中暂留 |
| file:// | 显示简明只读说明及启动方式；不呈现可编辑空表单，不请求认证接口 |

Tab 只是显示控制。每个服务端写接口仍须独立校验权限、CSRF 及配置版本。

## 12. 视觉与响应式规范

- 使用 `--docs-*` 颜色与字体变量；主色用于当前 Tab、主要保存按钮和焦点，错误、只读、来源类型有独立且克制的表达。
- 表单标签建议 13–14 px、正文约 14 px；不用当前 11.5 px 的小标签承载整页主要任务。
- 宽度 ≥1280 px：一行 Tab、完整表格、右侧详情抽屉。
- 768–1279 px：Tab 可横向滚动；表格优先保留名称、来源、状态、操作，次要统计移入详情。
- 小于 768 px：仓库改成摘要列表；点击编辑进入全屏详情；表单单列，底部操作栏不遮挡输入。
- 不把所有内容强行缩小到一屏；列表自然纵向滚动，详情区域有明确滚动边界。
- Tab 使用 `tablist/tab/tabpanel`、`aria-selected`、`aria-controls`；方向键、Home/End 切换，Tab 键进入内容。
- 使用原生按钮与真实链接，移除 `<a><button>…</button></a>` 嵌套交互元素。
- 抽屉有焦点管理、Esc 关闭及关闭后的焦点恢复；存在未保存仓库编辑时遵守统一草稿规则。
- 状态同时有文字或图标，不依赖红绿颜色区分。

## 14. 实施步骤与代码边界

1. **整理文案与结构**：在 `web/md2web_config.html` 创建固定 Tab、面板和局部状态容器；把内联大段 CSS 抽到 `web/md2web-config.css`；更新标题及过时说明。
2. **建立统一状态**：在现有脚本中分离已保存基线、配置草稿、运行状态、导航状态与敏感凭据编辑状态。先解决刷新覆盖草稿问题，再迁移表单位置。
3. **接入导航**：Tab、页内锚点、老 hash 兼容、前进后退、按需加载、权限显隐。
4. **重构仓库交互**：摘要列表、筛选、单仓库详情抽屉；保留现有稳定 ID、来源类型和写保护。
5. **整理保存流程**：全局保存、修改摘要、即时操作边界、409 保留草稿、保存与重建结果分开。
6. **迁移其他功能**：认证与凭据、用户权限、备份恢复、AI、缓存、配置方案；覆盖所有现有入口。
7. **构建与验证**：新增本地 CSS/JS 由 `setup_docsify.py` 复制并版本化，重建产物；不直接维护 `docs/html` 和 `docs/lib`。

第一阶段以布局和状态可靠性为交付范围。指标面板、新的灾难恢复、AI 模型测试、全站保存重建优化等不捆绑进入本次改造。已有接口不足以支持某个展示时，明确保留现状或单列接口工作。

## 15. 验收任务

| 场景 | 必须达到的结果 |
| --- | --- |
| 新建本地库 | 在仓库管理内完成必填配置，保存后可以打开入口，无需寻找 SVN 账号表单 |
| 新建 SVN 库 | 能找到默认凭据设置并返回原仓库编辑位置；清楚知道保存和拉取的先后关系 |
| 同步认证失败 | 从异常行直接进入当前凭据来源，看到具体错误，修正后重试 |
| 修改显示名 | 不改变稳定 ID、实际目录和凭据绑定 |
| 实际目录改名 | 明确旧/新路径、立即执行语义和阻塞条件；普通保存不能绕过接口 |
| 编辑 AI 后切回仓库 | AI 修改仍在，待保存栏覆盖两个 Tab 的变更 |
| 修改配置时刷新统计 | 编辑内容不被刷新请求覆盖 |
| 提升 SVN 用户为管理员 | 能找到用户、立即看到有效权限；不把 SVN 远端 ACL 描述成已改变 |
| 备份或修复 | 本区域显示真实结果和对象；危险操作不挤在普通按钮中间 |
| 切换方案 | 先处理未保存修改；预览与应用有区别；方案应用后全页状态一致 |
| JSON 编辑失败 | 保留文本和具体错误，普通表单不会静默覆盖 JSON |
| 另一个管理员已保存 | 409 后保留自己的草稿，可读取最新值比较 |
| 保存成功但重建失败 | 明确告知配置已写入，允许重试重建，不误报完整成功 |
| 会话失效、降权 | 私有 Tab 内容及时隐藏并清理，写操作不能继续 |
| 旧链接与窄屏 | 旧 hash 定位正确；键盘可用；不依赖横向拖动一张超宽表完成编辑 |

推荐按上述结构实施：优先把“找到功能、看懂状态、确认是否保存”三件事做清楚，再优化视觉细节。
