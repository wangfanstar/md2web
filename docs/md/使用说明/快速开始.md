# 快速开始

欢迎使用 md2web。把 Markdown 放进 `docs/md/`，运行构建脚本即可生成完全离线的文档站。

## 阅读区工具栏

每篇文档右上角都有一排按钮：

- **复制链接**：复制当前页面的链接地址（含 `#/` 路由，可直接分享给他人）
- **编辑 MD**：打开双栏编辑器——左侧 Markdown 源码按格式分色（标题层级、列表、代码块、公式），右侧实时预览（Mermaid、PacketDiag、KaTeX 公式、代码高亮）；`Ctrl+S` 直接写回 `docs/md/` 源文件（预览服务会自动重建），也支持另存为、下载、复制、还原与重新加载
- **下载 MD**：下载当前页面对应的 Markdown 源文件
- **下载本页**：把当前文档导出为自包含 HTML（含图片、图形与目录，可离线转发）
- **宽屏阅读** / **隐藏序号**：切换阅读布局与标题编号

编辑器常用快捷键：`Ctrl+B` 加粗 · `Ctrl+I` 斜体 · `Ctrl+K` 链接 · `Ctrl+M` 行内公式 · `Ctrl+Shift+M` 公式块 · `Ctrl+Alt+1/2/3` 标题 · `Ctrl+Shift+U`/`Ctrl+Shift+O` 无序/有序列表 · `Ctrl+Shift+K` 任务列表 · `Ctrl+Shift+C` 代码块 · `Ctrl+Shift+G` Mermaid · `Ctrl+Shift+D` PacketDiag · `Ctrl+S` 保存 · `Ctrl+/` 全部快捷键。

> 直连保存仅在 `python serve.py` 的本机预览下可用（局域网其他机器访问时接口拒绝写入）；`file://` 双击模式会改为「保存到文件」或下载。

左侧栏顶部还有「绘图预览」入口（<a href="lib/plot-playground.html" target="_blank" rel="noopener">lib/plot-playground.html</a>），可在线试写 Mermaid / PacketDiag 并下载图片。

## AI 助手

右下角「AI 助手」按钮（或 `Ctrl+Shift+A`）打开对话面板：它会先在本地 `search-index.json` 中检索相关章节，再把资料片段与问题一起发给您配置的大模型，回答下方列出引用来源，点击即可跳转。

配置入口在**左侧栏顶部的 `AI 配置` 图标**（对话面板右上角「⚙ 配置」同样可打开），包含：

- **服务商与密钥**：OpenAI 兼容 / DeepSeek / Ollama 本机 / Anthropic / 自定义，填写接口地址、模型、API Key、温度、系统提示与请求方式，点「保存并测试」验证连通性
- **资料范围**：按文件夹/文档勾选，回答只依据所选资料（不勾选 = 使用全部文档）
- **上传文档**：可选择本机的 `.md` / `.markdown` / `.txt` 加入检索（单个 ≤ 256 KB、合计 ≤ 512 KB，仅保存在浏览器 localStorage，不会上传或提交到仓库）；上传文档会出现在资料范围的「upload://」分组中
- API Key 只保存在浏览器 localStorage，不会写入仓库或上传服务端；公开仓库请勿把 Key 提交进任何文件
- 请求方式默认「自动」：浏览器直连失败（通常是跨域）时自动改走本机 `serve.py` 的 `/__ai/chat` 代理（仅本机可调用）
- 完全离线（双击 `index.html`）时检索仍可用，但调用模型需要网络，且只能直连、不能走本机代理
- 快捷动作：「总结本页」「文档概览」「解释选中」（选中正文文字后点击）

## 目录约定

- `docs/md/` 是唯一需要维护的目录，可自由创建子文件夹
- 图片无需登记，放在文档旁边或任意位置，用相对路径引用即可，例如 `![](images/flow.png)`
- 构建只处理 `.md` 文档；图片由浏览器直接加载

## 构建与预览

```
python setup_docsify.py
python serve.py
```

也可以直接双击 `docs/index.html` 浏览（file:// 模式，内容与搜索索引已内嵌）：该模式为**离线只读**，保留搜索、图形、公式与下载能力。

## 登录与编辑权限

默认 `python serve.py` 启动**认证编辑服务**（匿名可读、登录后可编辑）；`python serve.py --preview` 是只读预览，不提供任何写接口。

```
python3 -m pip install --user --no-index --find-links server/wheels -r server/requirements.txt   # 离线包（推荐；非 root 加 --user）
python3 -m pip install --no-index --find-links server/wheels -r server/requirements.txt            # 离线包（有写权限的账号）
python3 -m pip install -r server/requirements.txt                                                  # 或联网安装（仅服务机需要）
python3 serve.py                                     # Linux 推荐用 python3（3.6.8+ 全功能）
python serve.py                                      # Windows / 默认启动认证编辑服务（配置不存在会自动生成）
python serve.py --preview                            # 只读预览（无写接口）
python serve.py --bind 127.0.0.1                      # 仅本机访问（默认监听所有网卡，局域网可访问）
./start_linux.sh                                   # Linux：默认后台启动（日志 data/serve.log）
./start_linux.sh --stop                            # 停止后台实例（按 pidfile）
./start_linux.sh --status                          # 查看状态与进程（md2web-serve）
./start_linux.sh --foreground                      # 前台运行（Ctrl+C 停止）
```

局域网访问：服务默认监听所有网卡，启动日志会打印「局域网访问: http://<服务器IP>:8882」，同事直接用该地址即可打开；打不开时先放行防火墙端口：RHEL/CentOS 7 执行 `sudo firewall-cmd --add-port=8882/tcp --permanent && sudo firewall-cmd --reload`，Ubuntu 执行 `sudo ufw allow 8882/tcp`（启动时会检测 firewalld/ufw 并提示）。只允许本机使用时用 `--bind 127.0.0.1`。局域网内任何人都能看到登录页与文档，请务必修改默认管理员密码。

启动后刷新页面：

1. 侧栏顶部「设置」→ 用管理员账号登录（首次为 **admin / admin**，登录后请立即在窗口底部修改密码）。
2. 在「SVN 认证路径」填入管理员准备的路由（必须是**强制账号密码认证**的路径，可点「测试认证路径」验证；允许匿名访问的路径会被拒绝）。
3. 在「仓库映射」中填写 docs 目录与 SVN 地址（按目录段最长前缀匹配，如 `md/硬件设计` → hardware 库）。
4. 按需填写「AI 助手」默认值（接口地址/模型/Key，会下发给所有登录用户），保存即可生效，无需重启。

管理员打开「设置」还能看到**使用情况**（按 IP/账号的登录记录、账号使用量、用户总数、详细操作记录）与**文档统计**（每个文档的大小/更新时间/更新次数、文件夹大小、文档增删记录，点击表头可排序）。

「设置 → 仓库映射」可为每个文件夹分别设置 SVN 库与**更新频率（秒）**：服务会按频率自动拉取远端更新；正在编辑（有草稿）的文档不会被覆盖，编辑器会提示先合并并可查看「远端差异」，提交成功后展示本次差异。

编辑器左侧目录默认显示，点击章节会同时把源码与右侧预览定位到该处；「设置」窗口按 AI 助手 / SVN 与仓库 / 账号 / 信息查询 分 Tab 显示。
提交时会把文档里引用的 `images/` 图片一起存档到 SVN（审阅面板会列出将一并提交的图片）；「设置」窗口按 AI 助手 / SVN 与仓库 / 账号 / 信息查询 分栏显示。

仓库与站点结构：根 `index.html` 是按分组的总览页，每个仓库一个入口页 `index_<仓库名>.html`（独立搜索索引；只读/禁止合入的仓库不能提交），`index_all.html` 为全部文档合并视图；仓库配置在 `md2web_config.html`（管理员登录后可改地址、目录映射、更新频率、分组与权限，并可用「创建并拉取」自动创建目录并下载 SVN 内容）。

之后：

- 匿名读者仍可浏览、搜索、下载；右上角显示「登录」。
- 编辑者用**自己的 SVN 账号密码**登录（服务端通过认证路径验证；口令先校验，成功后以本机密钥加密保存在服务端数据库，提交与查询直接复用，换密码后重新登录会自动更新；旧版 svn 客户端会回退到命令行参数传口令）。
- 登录后打开编辑器：`Ctrl+S` 保存的是**个人草稿**（带版本号，其他标签页或本人更新会让旧版本保存返回冲突，不会覆盖）；工具条提供「历史」（草稿版本列表，可载入任一版本）、「差异」（已发布版本 ↔ 当前草稿的统一差异）、「载入最新」「放弃草稿」。草稿不会进入站点与搜索索引。
- **插入图片**：工具栏「图片」可多选文件；在源码区直接 `Ctrl+V` 粘贴剪贴板图片也可。登录后图片自动保存到**当前文档同目录的 `img/`**（不存在会创建、重名自动加 `-1`），并插入 `![名称](img/文件名)`；离线（file://）模式改为内嵌 data URL 并在状态栏说明。
- **没有 SVN 基线也能编辑**：文档在 `docs/md` 中尚未发布或所在目录未关联仓库时，编辑器会给出提示，可直接编辑并用 `Ctrl+S` 保存草稿；提交 SVN 时会作为新文件加入。
- **提交 SVN**：编辑器右上角「提交 SVN…」→ 填写提交说明 → 审阅面板显示目标库、精确文件与统一差异 → 点「确认提交」用**自己的 SVN 账号**提交；成功后站点会自动重建。提交只包含这篇文档，不会夹带其他文件夹或其他人的改动；远端基线过期时会明确报错而不是覆盖。「SVN 日志」可按当前账号查看目标库日志。
- **管理员**使用本机账号（默认 `admin / admin`）登录后同样可以本地编辑；提交时提示输入一次 SVN 账号，验证通过后会加密保存到服务端数据库，后续提交可复用。
- 会话默认 8 小时有效、闲置 30 分钟失效；服务重启后需重新登录。
- 写接口全部经过登录 + CSRF 校验；源文件写回使用版本校验，不再有"再次保存强制覆盖"。
- 修改 SVN 认证路径会让已有 SVN 用户会话失效（管理员会话保留以便继续配置）。

> 阶段一（登录与只读边界）、阶段二（个人草稿、版本历史、差异）与阶段三（多库提交、私有工作副本、外部同步）已实现。工程师生成本地编辑与 SVN 提交的习惯不受影响，网站也不采集本地编辑过程。

## 界面小技巧

- 阅读区右上角的按钮行（复制链接 / 查看源码 / 编辑 MD / 下载 MD / 下载本页 / 显示序号）在向下滚动时会**固定在顶部**。
- 「查看源码」无需登录：弹出窗口直接显示当前文档的 Markdown 源码，可编辑、实时预览，并「保存到本地」（不会改动服务端文档）。
- 从搜索结果进入阅读模式时，命中工具条与按钮行会上下并排显示，互不遮挡；离开阅读模式后按钮行回到顶部。
- 右侧「本文目录」固定**贴着窗口右缘**；其左边缘是可用鼠标拖动的调节线，向左拖变宽、向右拖变窄（宽度记忆在本机，刷新后保持）。
- 搜索框放大镜右侧的 ⚙ 图标用于展开/收起「范围 / 模式」筛选（默认收起节省空间，筛选生效时图标高亮）。
- 导出的独立 HTML 中，本文目录固定在**左侧导航**，正文在右侧滚动。目录会**高亮当前阅读的章节**并自动展开其上级；右上角有「隐藏」按钮，隐藏后屏幕右缘会出现「目录」小标签，点击即可恢复。分级标题左侧的箭头可折叠/展开子章节。
- 绘图预览页提供「复制源码」按钮，可把左侧源码一键复制回文档；绘图示例中的每个图形都配有源码对照。
- AI 助手面板：上传文档入口在**输入框上方**（不在配置弹窗里）；「历史」可查看与切换本机保存的历史对话，「新对话」开始一份新记录。
- 设置入口：侧栏顶部 HOME 图标旁的单个「设置」图标（含 AI 配置）。窗口内可配置：**我的 AI 设置**（服务商/接口/模型/Key/代理策略/**参考源码路径**/资料范围，仅存本机浏览器）、**服务端设置**（管理员登录后配置 SVN 认证路径、仓库映射与全站 AI 默认值）、管理员改密。
- 管理员登录：**本机管理员账号（默认 `admin / admin`）不需要 SVN 校验**，用页面右上角「登录」或设置窗口即可登录；侧栏会显示「管理员（本机）」。本机账号只能**本地编辑与保存草稿**；「提交 SVN…」时会提示输入一个 SVN 账号（仅本次合入使用，留在服务进程内存），因为仓库写入始终以真实 SVN 身份记录。
- 首页（`#/`）由构建生成，编辑器只提供只读预览并提示改从左侧目录打开 `docs/md` 下的文档；文档路由不带 `.md`（docsify 会去掉后缀）也能正常编辑与保存。
- 「参考源码路径」会随提问一起发给模型（如 `D:/repo/firmware` 或 `/srv/src/project`），便于 AI 回答时引用代码库位置。
