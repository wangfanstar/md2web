# 注册中断函数注意事项

> 适用于裸机 Cortex-M / 通用 MCU，并对照 RTOS（FreeRTOS、RT-Thread）与 Linux 内核驱动的差异。
> 文中示例为通用写法，具体寄存器名/API 以所用芯片与 SDK 为准。

## 1. 先理清「注册」到底做了哪几件事

一次完整的中断接入包含四步，任何一步漏掉都会表现为「中断不响应」或「进了中断但程序跑飞」：

1. **配置外设**：使能外设时钟、配置触发条件（边沿/电平、FIFO 阈值等）、**清除挂起标志**。
2. **配置 NVIC**：设置抢占优先级与子优先级、使能该 IRQ 通道。
3. **提供处理函数**：使启动文件向量表里的符号有实现（同名、`extern "C"`、链接不丢）。
4. **使能外设自身的中断位**（如 `USART_CR1_RXNEIE`）：NVIC 使能 ≠ 外设会发中断请求。

最常见的「顺序」坑：**先开 NVIC、后清标志**，结果一使能就立刻进一次中断（甚至死循环）。

## 2. 通用注意事项（与平台无关）

| 类别 | 要求 | 典型后果 |
|------|------|----------|
| 函数签名 | 必须与向量表/注册 API 要求的原型完全一致（`void f(void)` 或 `irqreturn_t f(int, void*)`） | 调用约定错乱、栈错位、HardFault |
| 命名 | 名字必须与启动文件（`startup_xxx.s`）或注册表中登记的符号**逐字符一致** | 链接到默认 `Default_Handler`，中断「静默」 |
| C++ | 用 `extern "C"` 声明，避免 name mangling | 链接找不到符号 |
| 执行时间 | ISR 内只做「取数据、置标志、清源」，重活交给主循环/任务/下半部 | 丢中断、主循环卡死、看门狗复位 |
| 阻塞调用 | 禁止 `delay/printf/malloc/文件 IO/阻塞锁` | 死等、堆重入、时序崩坏 |
| 可重入 | 同一 ISR 可嵌套触发时，函数内不能用非重入的静态缓冲区 | 数据错乱 |
| 共享变量 | 与主循环共享的变量必须 `volatile`；多字节读写用临界区/原子操作保护 | 编译器优化掉读、读到半更新值 |
| 栈深度 | 中断使用当前栈（Cortex-M 使用 MSP/PSP 之一），ISR 内少用大数组 | 栈溢出、随机 HardFault |
| 优先级 | 明确每个中断的实时性等级，数字方向（Cortex-M：**数值越小优先级越高**）不要记反 | 关键中断被低优先级抢占或反之 |
| 幂等 | 处理函数要能被重复进入而不产生副作用（先清标志再处理或反之，需按外设手册确定顺序） | 反复进中断、丢事件 |
| 注册失败 | 任何注册 API 都要检查返回值 | 中断根本没挂上却以为在工作 |

### 2.1 清标志的正确位置

- **大多数外设**：先读数据/清标志，再退出；只清「本次产生的」标志。
- **电平触发**：必须清源（例如读空 RX FIFO），否则退出后立刻再次进入。
- 有的外设要求「先清后读」，有的「先读后清」，**按参考手册**，否则会丢掉下一个字节。

### 2.2 `volatile` 与临界区

```c
static volatile uint32_t g_rx_count;   /* ISR 写、主循环读 */

void USART1_IRQHandler(void)
{
    g_rx_count++;                       /* 单字节自增在多核/嵌套下不原子 */
    /* ... */
}

/* 主循环读取多字节结构时关中断保护 */
__disable_irq();
snapshot = g_frame;
__enable_irq();
```

## 3. Cortex-M / 裸机要点

- **优先级分组**：先 `NVIC_SetPriorityGrouping()` 确定抢占/子优先级位数，再设各中断优先级；分组改晚了会打乱已配置的值。
- **优先级数值**：Cortex-M 只有高几位有效（常见 4 位，即 0–15），写 5 和写 6 在高位对齐后可能相同。用 `NVIC_EncodePriority()` 而不是手写魔数。
- **默认处理函数**：未实现的中断会落到 `Default_Handler` 的死循环里，表现为「程序停住」。调试时先确认 `SCB->VTOR`、向量表地址和实际符号。
- **不要依赖 `__weak` 空实现**：它只是让链接通过，不会告诉你「忘了写」。
- **中断里调用 HAL/库函数**：注意 `HAL_Delay()` 依赖 SysTick，SysTick 优先级低于当前中断时会**永久卡死**。
- **浮点**：Cortex-M4F 等带 FPU 的芯片，ISR 内用浮点会触发惰性压栈，增加延迟；高频中断建议整数运算。
- **动态注册**（如 `HAL_NVIC_SetVector()`、CMSIS 的向量表重定向）：只在启动阶段做，运行期改向量表要关中断并保证内存一致。
- **中断与低功耗**：进低功耗前确认唤醒源中断已使能且标志已清，否则 `WFI` 睡下去不醒或立刻醒。

## 4. RTOS 环境（FreeRTOS / RT-Thread）

**核心原则：ISR 里只能调用带 `FromISR` 后缀（或明确标注「中断安全」）的 API。**

### 4.1 FreeRTOS

```c
void UART_IRQHandler(void)
{
    BaseType_t woken = pdFALSE;

    /* 只搬数据，不发信号量以外的重活 */
    xSemaphoreGiveFromISR(g_rx_sem, &woken);
    portYIELD_FROM_ISR(woken);      /* 必须在 ISR 末尾调用 */
}
```

- `xQueueSendFromISR` / `xSemaphoreGiveFromISR` / `vTaskNotifyGiveFromISR` 之外的 `xQueueSend`、`vTaskDelay` **禁止**在 ISR 使用。
- 中断优先级数值必须 **≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`**（数值更大 = 优先级更低）才能调用 FreeRTOS API；更高优先级的中断不可调用任何 RTOS API，也不受临界区保护。
- 每个 ISR 结束前检查 `woken` 并 `portYIELD_FROM_ISR()`，否则要等下一个 tick 才切换。
- `configASSERT()` 在开发阶段务必打开，能捕获「在错误优先级里调 API」。

### 4.2 RT-Thread

- ISR 中只能使用 `rt_*_isr` 或文档标注中断安全的接口；不能用 `rt_thread_mdelay`、`rt_mutex_take`。
- 由 `rt_hw_interrupt_install()` / `rt_interrupt_enter()/leave()` 的框架接管时，不要自行改动 `rt_interrupt_nest`。
- 用 `rt_sem_release` / `rt_mb_send` 唤醒线程，把耗时逻辑放到线程里。

### 4.3 通用 RTOS 注意

- 临界区（关中断）尽量短，别把耗时操作放进 `taskENTER_CRITICAL()`。
- ISR 与任务共享的数据，要么用队列/信号量交接所有权，要么显式加临界区。
- 中断优先级与任务优先级的**语义不同**（数值方向可能相反），配置时写注释说明。

## 5. Linux 内核驱动（对照）

```c
static irqreturn_t my_handler(int irq, void *dev_id)
{
    struct my_dev *dev = dev_id;          /* 共享中断必须校验 dev_id */
    u32 status = readl(dev->base + REG_STATUS);
    if (!(status & IRQ_BIT))
        return IRQ_NONE;                  /* 不是我的中断，交还内核 */

    /* 上半部：只清中断、取最小数据，不做可能睡眠的操作 */
    writel(IRQ_BIT, dev->base + REG_STATUS);
    return IRQ_HANDLED;
}

ret = request_irq(irq, my_handler, IRQF_SHARED | IRQF_TRIGGER_RISING,
                  "my-dev", dev);
if (ret)
        return ret;                       /* 必须检查 */
```

要点：

- `request_irq()` **必须检查返回值**；`dev_id` 非 NULL（共享中断时用于区分与注销，且必须唯一）。
- 共享中断：handler 里先判断「是不是我的」，不是就返回 `IRQ_NONE`；注销必须传**同一个** `dev_id`。
- 上半部**不能睡眠**（不能 `mutex_lock`、`kmalloc(GFP_KERNEL)`、`copy_to_user`），耗时/可睡眠逻辑放 tasklet、workqueue 或线程化中断（`request_threaded_irq`）。
- 触发类型按硬件实际配置一致（`IRQF_TRIGGER_*` 与设备树/硬件寄存器不匹配会丢中断或狂进）。
- 注销用 `free_irq()`；驱动移除路径用 `devm_request_irq()` 更省心，但注意 `devm` 释放顺序与设备生命周期。
- 中断上下文不能访问用户空间、不能用可能睡眠的自旋锁；多核共享数据用 `spin_lock_irqsave()`。
- 调试：`cat /proc/interrupts` 看计数是否增长（增长但业务无响应 = handler 判断条件写错；不增长 = 未注册/未使能/触发类型错）。

## 6. 常见故障速查

| 现象 | 优先排查 |
|------|----------|
| 完全不进中断 | 外设时钟/中断位未开、NVIC 未使能、向量名与启动文件不一致、链接被优化掉（`-ffunction-sections --gc-sections` 误删） |
| 进一次就不再进 | 标志没清、电平触发源未消除、忘了 `IRQ_HANDLED` 之外的 ack 操作 |
| 疯狂反复进入 | 触发方式与硬件不符、清标志写错寄存器位、电平一直有效 |
| 偶发 HardFault / 跑飞 | ISR 栈溢出、函数原型不匹配、ISR 内大数组、未 `extern "C"` |
| 主循环卡顿/丢数据 | ISR 内做了耗时操作、ISR 里调用了阻塞 HAL/RTOS API |
| 多字节数据偶发错乱 | 缺 `volatile`、缺临界区、非原子读改写 |

## 7. 上线前检查清单

- [ ] 外设时钟、中断使能位、NVIC 通道、触发条件四者都已配置
- [ ] 处理函数名与向量表/注册表一致，C++ 项目已 `extern "C"`
- [ ] ISR 执行时间已测量（建议 ≤ 数十微秒量级），重活已移到主循环/任务/下半部
- [ ] ISR 内无 `delay`、`printf`、`malloc`、阻塞锁、可能睡眠的调用
- [ ] 与主循环共享的数据有 `volatile` + 临界区/原子保护
- [ ] 中断优先级已按实时性规划，未超过 RTOS 允许调用 API 的优先级上限
- [ ] 每个可能失败的中断注册/使能调用都检查了返回值
- [ ] 压力测试：最高频率触发下不丢事件、不溢出、不触发看门狗
- [ ] 注销/反初始化路径正确（`free_irq` / 关闭 NVIC 与中断位）
