0. 总览：四个 IP 的关系与分层

这四份手册描述的是一套通道化（Channelized）以太网子系统，覆盖 1G~400G，并可复用 PHY 支撑 FlexE / SPN。层次自上而下为：CEMAC（MAC/RS 层）→ CEPCS（PCS 编码层）→ CEFEC（RS-FEC 编解码）→ Serdes，而 CESOCX16_WRAP 是把上述 IP 加 FlexE、1GE、10GWIS、配置译码、复位、寄存器 Mux 打包起来的顶层封装。

0.1 关键分工速记（易混点）

问题答案
FEC 寄存器在哪？在 CEPCS 里。CEFEC 自身无寄存器，CEPCS 通过 CEPCS_FEC_BYPASS_CFG_O、CEPCS_DEGRADED_SER_EN_O 等引脚下发配置，并把 CEFEC 状态存入 MDIO 寄存器。
速率/FEC 算法怎么选？顶层通过 引脚 CFG*_<速率>_CH_I 给 CONFIG_GEN 译码，不是寄存器。
软复位怎么做？CESOC_REG 的软复位是非自清（写 1 置位、写 0 释放）；各 IP 内部软复位是自清(SC)。高速率通道需多 bit 同时置位。
1588 谁做？CEMAC 内 TSU 做 1-step；2-step 需配合 CEPCS 内的 HETS（1ns 精度）。
FlexE 走哪条路？CEPCS 提供 66b 数据口（FLEXE_EN_I 置位后走 FLEXE_TX?_66B_I），64/66B 编解码在 FlexE 侧完成，PCS 的错块计数/LPI/RX fault 功能失效。

0.2 系统总体分析：三条正交通路

把四份手册放在一起看，CESOCX16_WRAP 不是“MAC + PCS + FEC + FlexE”的简单堆叠，而是围绕通道（channel）和时钟域组织起来的一套系统。所有模块的交互可以拆成三条正交通路：数据面负责帧/码字搬运，控制面负责速率、FEC、复位和寄存器，时间面负责 1588 / FlexE 时间戳。把这三条通路分开看，绝大多数“信号为什么接不上/寄存器为什么写不进去”的问题都能快速定位。

① 数据面（Data Plane）

用户 FIFO ↔ CEMAC ↔ MII ↔ CEPCS ↔ Serdes；CEPCS 与 CEFEC 之间是码字环回（TX 编码、RX 解码），FlexE 则从 CEPCS 的 66b 口旁路 MAC/PCS 编码。核心约束是通道绑定与跨时钟域 FIFO。

② 控制面（Control Plane）

APB 主机 → 地址译码 → CESOC_REG / CEPCS / CEMAC / FLEXE TOP / FLEXEX8_REG / SPN；CEPCS 内部再用 MDIO 式寄存器访问代管 CEFEC。速率与 FEC 算法则走引脚 + CONFIG_GEN，不是寄存器。

③ 时间面（Time Plane）

80-bit 系统实时钟同时送给 CEMAC TSU 与 CEPCS HETS；TSU 负责 1-step 和 2-step 的报文侧处理，HETS 提供 PHY 侧高精度打戳；FlexE 另有基于 OH frame 的 80-bit 时间戳。

0.2.4 关键耦合点与风险清单

  1. FEC codec 的 200G 上限是硬约束。400G 必须用两个 codec（码字 A/B），200G 可用一个；CEFEC_CFG*_IS_CWA_I 必须与 CEPCS 的码字分发一致。改 IS_CWA 或 DE_SER_EN 前要同时复位 TX 与 RX，否则内部中间结果不清。
  2. PCS lane / FEC lane 的映射随速率变化。400G/200G/40G 的 lane mapping 记录的是 PCS lane，100G/50G 记录的是 FEC lane；调试 deskew/AM 锁定时不要拿错表。
  3. 复位是“非自清 + 多 bit 齐置”的组合。CESOC_REG 写 1 断言、写 0 释放；各 IP 内部软复位是 SC。200GR4 通道 0 要 bit[3:0]，100GR2 通道 2 要 bit[3:2]，50GR2 通道 4 要 bit[5:4]，10G 通道 9 要 bit[9]。上电顺序：PRESETN_I 先释放 → T1 → SYS_RESET_I 释放 → T2。
  4. 三条异步边界不要混。CEMAC 的 FIFO（SYS_CLK）↔ MII_CLK；CEPCS 的 MII_CLK ↔ SD_TX/RX_CLK（80b AFIFO + 16×128×41 deskew memory）；FlexE 的 PHY Mux 也跨到 PCS 域。跨域信号必须按各自 FIFO 的 valid/ready 或 DC 规则处理。
  5. FlexE 抢 PHY 后，PCS 的统计/环回语义会变。FLEXE_EN_I 置位后 64/66 编解码在 FlexE 侧完成，PCS 的错块计数、LPI、RX fault 功能失效；改 FLEXE_PHY_SEL_I / CEPCS*_FLEXE_EN_I 后必须用 CESOC_REG 0x06/0x07 复位对应 PHY 通道。
  6. APB 地址换算有三类规则。CESOC_REG / CEMAC / CEPCS / FLEXEX8_REG 丢 bit[1:0]；FLEXE TOP 与 FLEXE SPN 不丢。CEPCS 是 16-bit 半字寄存器，读回高 16 bit 恒 0，实际只有一半空间有意义。
  7. HETS 不是所有模式都能用。HETS_EN 默认全开，但 10GE / 10GWIS / 1GE / 25G-bypassFEC 即使置 1 也不工作；2-step 依赖 HETS 时，HETS 复位/不响应会导致 TS FIFO 溢出，固件必须写 Soft_Reset bit2/bit3 重同步。
  8. 计数器读取有顺序。64-bit / 22-bit 计数器先读低位，高位在低位读的瞬间锁存；FEC 的 RC 计数器在读后约 55 个 MII 时钟（或 5 个 APB 时钟）才清零，同一地址不要连读。
  9. 100GR10 是特殊路径。它占用 Serdes lane 8/9，且 lane 8/9 必须为 NRZ；CEPCS_100G_NOFEC 宏会额外例化 20 条 PCS lane 的 lane lock/deskew，不定义时 100GR10 的无 FEC 模式不可用。
  10. 低频 CEFEC 是“半带宽 + 重映射”。CEFEC_CFG_LOW_FRQ_EN_I=1 后时钟可减半，但最大带宽也减半，且 4CH/8CH 的通道 ID 分配与 RX 输出序列都会改变；不要拿正常模式的 Type 表直接套。
总体结论：这套 IP 的“可配置性”主要来自三处——引脚（速率/FEC 算法）、APB 寄存器（软复位/工作模式/阈值）、FlexE 绑定（PHY 选择/日历/实例使能）。三者没有统一的配置数据库，集成时建议自建一张“模式 × 通道 × FEC 算法 × PHY 端口 × 复位 bit”的表，否则很容易出现“数据面通了但 FEC 没配对”或“PHY 选了但 PCS 没复位”的问题。

1.4 Flow Control Mux（流控汇聚）

最多 12 个以太网通道，每通道原本有独立 FC 接口；为适配 H3C 定义的流控机制，增加了 Mux 逻辑，把所有通道汇聚成一组接口。

TX 侧流程

  1. FC_TX_VAL_I 拉高时，FC_TX_CH_ID_I 指定由哪个通道发起流控帧。
  2. 与 FC_TX_VAL_I 同拍：FC_TX_IS_PAUSE_I=1 → MAC 用 FC_TX_PAUSE_TIMER_I 组 Pause 帧；=0 → 用 FC_TX_PFC_TIMER_I 组 PFC 帧，并用 FC_TX_DATA_I 使能对应队列定时器。
  3. MAC 必须发完当前帧才能插入 Pause/PFC，可能挂起若干拍；用户逻辑必须等到 FC_TX_RDY_O 拉高才能发新请求。
  4. FC_TX_AL_DONE_O 指示某通道的 PFC/Pause 定时器即将耗尽，用户可再次请求刷新。

RX 侧流程

  • 收到 Pause/PFC 且该通道尚未被流控 → FC_RX_VAL_O 拉高 1 拍；若是 Pause 则 FC_RX_IS_PAUSE_O 同时拉高 1 拍。
  • FC_RX_CH_ID_O 指示通道号；FC_RX_DATA_O 指示需被控的队列，Pause 时为 8'hFF。
  • 定时器计数结束（解除流控）时同样上报：此时 Pause 对应 FC_RX_DATA_O = 8'h0。
仲裁规则：12 个通道共用该接口。若多个通道同时收到 Pause/PFC，先上报通道号最小的，其余依次逐个上报。

2.3 以太网帧结构

帧格式字段依次为：Packet Head（前导+SFD）→ Address（DA/SA）→ Length/Type → Payload Data → Pad → FCS → IPG。要点：

  • Address：DA bit0=0 为单播；bit0=1 且其余位非全 1 为多播；全 1 为广播。
  • FCS：CEMAC_FCS 生成 32-bit FCS。100G 模式下每拍算 16 字节 CRC；低速模式表现为两个独立 CRC 生成器，各算 8 字节。
  • IPG：由 IPG_CFG 寄存器 bit[7:0] 指定，默认 12，可设 8~24；bit[15] 使能 AM IPG 补偿模式，bit[31:16] 指定补偿间隔。

2.6 流控（Flow Control）

2.6.1 Pause 与 PFC

  • Pause 发送：TF*_SEND_PAU_I 单拍脉冲 → MAC 自组装 Pause 帧。定时器来源由 MAC_CFG[22] PAU_TIMER_PIN 决定：1=取自引脚 PAU_TIME_I，0=取自寄存器 PAUSE_TIMER（默认 1）。
  • PFC 发送：TF*_SEND_PFC_I + PFC_VEC_I[7:0]（每 bit 一个队列）；定时器来自 PFC_TIMER01/23/45/67 或引脚 PFC_TIME_I[127:0]。
  • Pause 帧识别：除标准组播地址外，还可用 DMAC_PS_ADDR0/1 自定义 48-bit 目的地址来识别 Pause 帧。
  • 丢弃策略：MAC_CFG[20] PAU_DISCARD（默认 1）= 将所有收到的 Pause/PFC 帧标记为错误帧丢弃。
  • 暂停发送：MAC_CFG[10] PAUSE_STOP_EN = 收到普通 Pause 后 MAC 停止从 FIFO 取新帧。
  • ALDONE 阈值：由 PAUSE_TIMER_ALDONE_THRES[15:0]（默认 0x4）设定，定时器倒数到该值时拉高 ALDONE。

2.6.2 Preamble Replacement（HiGig / 前导替换）

该功能复用 PFC 端口实现自定义 16 字节 message：

  1. 发送：拉一拍 TF*_SEND_PFC_I，把 message 内容放在 TF*_PFC_TIME_I[127:0]。
  2. MAC 自动把 byte0 替换为 SOM、byte15 替换为 CRC8，并在 IPG 间隙发到 MII。
  3. 发送完成回 TF*_SEND_PFC_ACK_O，之后可发下一个请求。
  4. 接收：RF*_PFC_UPDATE_O[0] 拉高表示收到 message，内容在 RF*_PFC_TIMER_O[127:0]。CRC8 校验失败的 message 会被直接丢弃、不上报。

2.9 MDIO Master

2.9.1 地址路由：MAC 寄存器还是 PHY 寄存器？

关键规则：MDIO Master 用 CEMAC_REG_PADDR_I[12] 做地址分流——bit12=1 → 访问 CEMAC 核寄存器；bit12=0 → 翻译成 MDIO 访问 PHY。因此 MAC 寄存器空间被限制在 0x1000~0x1FFF 的 4KB 窗口内（实际每核 0x100），而 0x0000~0x0FFF 的访问会落到 PHY。

2.11.3 1-step / 2-step 的 TX 处理流程

1-step（MAC 自己改包）

  1. 系统时钟通常由自由运行计数器产生，40-bit 或 64-bit；低 32 bit 表示纳秒，为达到 1ns 精度计数器按亚纳秒步进（例如 bit[31:2] 计 ns、bit[1:0] 计 0.25ns）。
  2. TF*_FS_I 与 TS*_TX_IS_PTP_I 同拍有效时，MAC 从用户取 16 字节 PTP 头；若头内 bit[120]=1，则为该帧生成时间戳并写入 Correction Field。
  3. MAC 在检测到 SFD 时从自由运行计数器抓取 40-bit CAPTURE_CF。
  4. 按 FLAGS 字段计算最终 CF：FLAGS.bit2 与 CAPTURE_CF[39:32] 是否 <128 共同决定是否做 2⁴⁰ 量级的修正；具体公式以手册 Table 9-1 为准。
  5. 若 FLAGS.bit1=1，更新 UDP checksum：FINAL_CS = PARTIAL_CS + checksum(CAPTURE_CF)；随后按正常流程重算 CRC。
  6. 发送完成拉 TS*_TX_1STEP_ACK_O 单拍，系统才能发下一个 1-step PTP 帧。
1-step 的两个硬性要求：① 16 字节 PTP 头必须被 MAC 丢弃，不能出现在任何 MAC 帧里；② 若做透明时钟（TC）驻留时间修正，用户必须把入口到达时间 / Frame ID 提供给 MAC TX，否则只能改 CF 的固定偏移。

2-step（MAC 只报时间，不改包）

  1. MAC 确认是 2-step PTP 头后，把整段 16 字节头写入 Header FIFO。
  2. 若 TS*_EN_HETS_I=0：MAC 自己抓时间戳，写入 TS FIFO；TS 非空时从 Header FIFO 取一项，把 bit[103:64] 替换为 40-bit 时间戳。
  3. 若 TS*_EN_HETS_I=1：MAC 通过 TS*_TX_GET_TS_O 发请求，并用 TS*_TX_HETS_ID_O[2:0] 发出事务 ID；HETS 返回 TS*_TX_HETS_ID_I[2:0] 做事件关联，时间戳写入 TS FIFO 后按上一步替换。
  4. 用户通过 TS*_TX_RD_EN_I 单拍脉冲读走一个时间戳；TS*_TX_RDY_O 表示可读，TS*_TX_FULL_O 表示 FIFO 满（此时 MAC 可能丢弃时间戳）。

RX（1-step / 2-step 相同）

  • RX 对每一个收到的 MAC 包都上报 40-bit 时间戳 TS*_RX_O[39:0]，在 RF*_FS_O 拉高时有效。
  • TS*_EN_HETS_I 决定时间戳由 MAC 自己产生还是向 HETS 请求；时间戳生成期间 MAC 会把收到的帧暂存在 RX FIFO，生成后与帧起始对齐输出。
  • CEPCS 侧通过 TX_MAC_TS_CLR_O（PCS TX 复位时清 MAC 旧时间戳/头）和 RX_LINK_READY_O（=0 表示链路 down）参与重同步。

3.4 TX 功能块

  1. 通道化 64/66b 编码器：把 MII 数据（每 lane 64bit data + 8bit ctrl）编码为 802.3 Clause 49（10G/25G）或 Clause 82（40G~400G）定义的传输码。数据通路宽度最多 8 条 MII lane。
  2. 加扰器（Scrambler）：为 10G~100G 开发，实现 Clause 49.2.6，在一个 MII 时钟周期内完成全部 8 条 lane。
  3. AM 插入：CEPCS_TX_100G_AM_INS 内含 8 个 66b AM 插入实例。lane 0/2/4/6 用 CEPCS_TX_128B_AM_INS（132-bit 数据总线 = 2 个 66b 块），支持 10G~100G；lane 1/3/5/7 用 CEPCS_TX_66B_AM_INS，仅需支持 10G~50G。
  4. 100G 有 FEC 时，AM 在 FEC 重映射之后插入；其余情况 AM 图样与 802.3 对应图样一致。AM 插入过程中，插入实例会拉低 data valid，暂停该 lane 上游所有功能块。
  5. 8×66 Buffer：每 lane 一个 10 深 × 66 bit 缓冲，把 AM 插入后的 1×66b 或 2×66b 数据重排成 4×66b，送往 transcoder；仅用于 25G/40G/50G/100G。
  6. 264/257 Transcoder：把 4 个 64b PCS block 转成 257b；AM 不参与 transcode，直接旁路到 scrambler。25G/50G 还会在 257b 尾部生成并附加 am pad-bit。模块分上下两组，分别服务 lane0~3 与 lane4~7。
  7. 400G Scrambler：对 transcoder 送来的两路 257b 做自同步加扰，多项式与 Clause 49 相同：G(x)=1+x³⁹+x⁵⁸；模块内有一级 buffer，仅用于 200G/400G。
  8. 400G AM 插入：400G/200G R4 取两路 257b、200G R8 取一路 257b。400G 每 81920 个 514-bit block 插一次 AM，200G 每 81920 个 257-bit block 插一次；定义 CEPCS_SHORT_AM 后仿真周期缩短为 640 个 block。CM/UM 图样默认与 802.3 119.2.4.4 一致，可通过 MDIO 修改；pad bit 为 PRBS9（x⁹+x⁵+1）。
  9. 257/320 Gearbox（8 个）：每 20 个有效 257b 周期产生 17 拍有效 320b，构成 5140-bit 数据块；码字起始/结束分别在第 1 拍与第 20 拍给出。内部 280-bit buffer 保存新输入与剩余数据。200G/400G 改用 2×514/640 Gearbox（560-bit buffer）；RS272 低延迟模式下码字周期从 20 拍降到 10 拍（2570-bit）。
  10. 2×320 Mux：25G/50G/100G 下把四条 lane 的 320b 按序 mux 到一个 FEC codec；200G/400G 下把 640b 做 10-bit 符号轮转，形成 mA/mB 两路送给两个 codec。
  11. TX 640 Demux + 8× 异步 FIFO：从 codec 收回编码数据，按模式分发到 8 个 16 深 × 80 bit 异步 FIFO（MII→Serdes 时钟域），并用反压阈值暂停前级。最后经 80→64b / 80→32b / 66→32b 三种 Gearbox 输出到 Serdes。

3.5 RX 功能块

  1. 16 × Lane Lock：CEPCS 从 8 条 Serdes lane 取数后，按 bit 级 demux 成 16 条数据流。每个 Lane Lock 块完成 AM 锁定 + 66-bit 块锁定，并提供 32-bit → 40-bit 的 gearbox 功能。
  2. Deskew 块：完成全部以太网通道的 deskew 与重排序，并用 16 个异步 FIFO 实现跨时钟域。含 16 个 FIFO 控制块控制 16 块外部 memory，每块 128 深 × 41 bit 宽；写侧工作在 Serdes 时钟域，读侧工作在 MII 时钟域。
  3. 若定义 CEPCS_100G_NOFEC，会额外例化 lane lock 与 deskew 逻辑，以支持 802.3ba Clause 82 定义的 66-bit 块与 20 条 PCS lane deskew。
  4. 640 Demux + 去交织：从 deskew 模块接收 8×80 bit 数据，去交织后重建原始码字流送往 FEC codec，并同时生成码字起始/结束指示。
  5. 2×320 Demux：从 FEC codec 取 320-bit 数据 + 10-bit 控制消息，按通道号 mux 进 RX 320/257 Gearbox；200G/400G 先按 10-bit 单位分发。
  6. RX Gearbox：8 个 320/257（100G/50G/25G）或 2 个 640/514（400G/200G），去掉剩余 parity bit，产生 20 拍有效数据；PCS block 同步头损坏指示也在此产生。
  7. 400G AM 移除：400G 每 8192 个码字、200G 每 4096 个码字周期性移除 AM；100G/50G/25G 旁路。
  8. 400G Descrambler：对 400G/200G 的两路 257b 解扰（一级 buffer）；100G/50G/25G 旁路到 RX transcoder。
  9. RX Transcoder：把两路 257b（400G/200G）或一路 257b（100G/50G/25G）反变换为 4×66b，按通道号送到对应 lane；400G/200G 只使用 ch0/ch4。若同步头损坏或 PCS block 格式错，会故意损坏 sync-header 上报。
  10. 4×66 Buffer：每 lane 4 深 × 66 bit，把 4×66b 转成 1×66b 或 2×66b 送 AM removal；仅 25G/40G/50G/100G。
  11. AM Removal + BIP：10G~100G 的 8 个 lane 子块在 AM 出现时拉低 data valid 完成移除，并在此检查 BIP。
  12. 66b Descrambler：10G~100G 解扰，引入 1 个 MII 时钟延迟。随后是通道化 64/66b 解码器（Clause 49/82），解码需要 3 个 MII 时钟，最后送 MII。
TX 侧对称流程（§3.4 补充）：257/320 Gearbox 之后是 2×320 mux。在 25G/50G/100G 下，它把四条 lane 的 320 bit 数据按序 mux 到一个 FEC codec；在 200G/400G 下，收到的 640 bit 数据会做 10-bit 符号轮转分发，形成 符号消息 mA 与 mB 送往两个 FEC codec 做 RS 编码。

3.7 软件接口：CEPCS 寄存器映射

寻址规律（背下来省很多时间）：CEPCS 每个以太网通道占一段 0x200 的地址空间，通道 n 的基址为 0x000 + n×0x200；FEC 寄存器基址为 0x100 + n×0x200。

4.5 RX 输出序列（§3.3.2）

CEFEC 会周期性产生一个基本输出序列：由 10 个时钟周期组成 —— 4 拍有效数据 + 1 拍全零无效 + 4 拍有效数据 + 1 拍全零无效。若无有效数据，该位置用全零填充。

4.6.2 Bypass Indication（§3.3.3.3）

  1. 正常模式：发现 UE 时，CEFEC 通过故意损坏 66-bit 块同步头向 PCS 子层指示错误，使 PCS 丢弃全部完全或部分落在该码字内的 ≥64 字节的帧。
  2. 使能 BYPASS_INDICATION：可降低 CEFEC 引入的延迟；同时 CEFEC 执行额外错误监测 —— 统计连续 8192 个码字中检出的符号错误数。
  3. 当 8192 码字内符号错误数超过 K，CEFEC 将 CEFEC_RX*_BP_CORR_IND_O 拉高 60ms ~ 75ms；PCS 据此把 hi_ber 置为 true，并在该时段内持续损坏 66-bit 块同步头。

4.6.3 Bypass Correction（§3.3.3.4）

① 使能后，CEFEC 仍尝试计算当前码字的 syndrome，syndrome 非零即判为 UE。
② 互斥约束：使能 BYPASS_CORRECTION 时不得同时使能 BYPASS_INDICATION。
③ 速率限制：按 802.3，只有 25G 与 100G 支持 bypass correction。

4.6.4 Degraded SER（§3.3.3.5）

  1. 使能 DEGRADED_SER 后，CEFEC 在连续不重叠的 DEGRADED_SER_INTERVAL 个码字块内统计符号错误数。
  2. 当某个码字是 UE 时，符号错误数按 +16 累加。
  3. 累计值超过 DEGRADED_SER_ACTIVATE_THRESHOLD → 置位 DEGRADED_SER。
  4. 每个 interval 结束时，若累计值小于 DEGRADED_SER_DEACTIVATE_THRESHOLD → 清除 DEGRADED_SER。
  5. DEGRADED_SER_EN 撤销 → DEGRADED_SER 立即清除。

5.3 上电初始化推荐流程

  1. 先释放 PRESETN_I（低有效），等待 T1 ≥ 5 个 PCLK。
  2. 确保所有时钟已正常工作，再释放 SYS_RESET_I，等待 T2 ≥ max(10×SYS_CLK, 5×PCLK)。
  3. 通过 CFG0_*/CFG1_* 引脚给定速率模式与 FEC 算法（DC 时序，功能模式下 SCAN_MODE_I 必须为 0）。
  4. 如需 FlexE：配置 FLEXE_PHY_SEL_I、FLEXE_INST_EN_I、CEPCS*_FLEXE_EN_I，随后必须用 CESOC_REG 0x06/0x07 复位对应 PHY 通道。
  5. 按需写 CESOC_REG 软复位寄存器（写 1 断言 → 写 0 释放，高速率通道多 bit 齐置）。
  6. 配置 MAC：MAC_CFG(0x00)、FIFO 阈值(0x01/0x02)、JUMBO_LENGTH(0x03)、源地址(0x04/0x05)、IPG_CFG(0x06)、流控定时器(0x07~0x0B)。
  7. 配置 PCS/FEC：经 MDIO 地址空间写 Control 1、FEC Control、degraded SER 阈值/间隔。
  8. 轮询状态：CEPCS*_LINK_RX_STATUS_O、AM_LOCK_O、DESKEW_DONE_O、FEC Align status。
